# 城市规划展示与简模细节升级方案

方案日期：2026-11-04。2026-11-05 更新：V1–V3 已实施，见[实现与验收](CITY_VISUAL_V1_V3.md)；V4–V5 保留为后续方案。下文保留总体设计和目标预算。

## 1. 升级目标

保留现在的简模示意风格，把城市展示提升为**可近距离检查的建筑规划沙盘**。远景读得懂区域结构，中景看得清街区和院落，近景能够判断门朝哪里、道路怎样接入、共墙和通院关系是否合理。

采用统一的哑光色块、清楚的体块和少量结构细节。增加的精度优先服务于入口、边界、楼层、屋檐、接地与公共空间的辨认。保持已完成的自然地形与低重复纹理风格，建筑表面以纯色和极弱变化为主。

本轮规划覆盖六个节点的展示及最终场景：环境底图、区域布局、道路、地块、建筑、城防、公共院区、市场与后院、田园，以及选择、标注和诊断。写实贴图、室内装修、人物交通模拟和正式游戏资产不在本方案内。

### 三类精度分别处理

- **几何精度**：道路和地面贴合更可靠；屋顶有厚度，门窗有清楚边界；城门和院门留出真实开口。
- **语义精度**：看得出主次路、临街面、后院、公共建筑、保护通道和问题位置；同一种信息在各节点含义一致。
- **观察精度**：近景能看清细节，线宽和标签随尺度管理，选中对象可定位和追溯。

视觉模型必须依附现有有效结果。装饰随机数独立于生成算法；改变外观、标签或显示模式不能改变道路、地块、建筑、城门和通道数据。

## 2. 当前实现与问题

依据当前源码、已有规划截图，以及最新 `artifacts/terrain_visual/less_tiling/` 城镇/市场截图整理。规划截图早于地形美术更新，仅用于检查其规划图层与界面；本次没有新增引擎验证。

| 现状 | 对查看效果的影响 | 对应升级 |
| --- | --- | --- |
| 区域通过透明色块和名称展示，城防为平面走廊 | 看得出大致范围，但缺少城门与墙体的空间关系 | 区域轮廓层级、示意墙体和门洞 |
| 路网已有定型占地、路口和来源边界 | 渲染仍以平面色带为主，路肩、广场和院地难以区分 | 统一贴地表面和边缘表达 |
| 地块默认绘制大量同权重白边，多个节点有独立色表 | 远景线条拥挤，切换时颜色语义不稳定 | 分尺度显示与统一用途配色 |
| 建筑已有双坡屋顶、门片、台阶、楼层和共墙数据 | 近景墙面空白，檐口和单体分界弱 | 屋顶厚度、门窗、墙脚及立面节奏 |
| 教堂已有主殿/可选塔楼，修道院已有翼部组合 | 公共体量仍缺少足够的入口和立面识别特征 | 在现有体量内强化公共建筑特征 |
| 场景已有井、棚、摊位、长凳、储物和围栏 | 同类物体轮廓接近，院门与通道缺少视觉引导 | 丰富少量共享简模并突出真实出入口 |
| 多个预览使用统一抬高和关闭深度测试 | 适合二维分析，但斜看可能有漂浮与穿透观感 | 区分实体展示、分析覆盖与显式透视检查 |
| 部分选择/切层会重建整体预览，场景拾取遍历三角形 | 增加细节后可能放大刷新与选择成本 | 独立高亮、缓存和空间查询 |
| 左右面板同时常驻，规划参数和查看选项混合 | 默认画面有效观察区域偏小 | 折叠底图面板、集中查看工具和对象详情 |

默认种子最近已有记录包含 90 条路段、848 个地块、654 个建筑体量与 1200 个附属物。这是建立新展示基线的测试规模，不是全局数量上限。

## 3. 一套场景，三种查看模式

节点选择继续负责“生成哪一步”，查看模式负责“怎样看结果”。两者分开，跨节点保留相机、查看偏好和仍有效的选择。

| 模式 | 主要画面 | 默认显示 |
| --- | --- | --- |
| **简模展示** | 自然地形、实体道路、建筑、城防和院落，正常遮挡与阴影 | 少量地标名称；悬停和选中后才显示尺寸及局部轮廓 |
| **规划分析** | 降低底图对比，突出用途、边界、建筑带和通道 | 一次选择一个主要分析主题，辅以必要上下文和图例 |
| **问题检查** | 中性简模背景，加问题标记和选中问题的局部证据 | 问题清单、定位、来源、原因；需要时显式开启透视检查 |

规划分析可选区域用地、路网/道路占地、地块用途、建筑带与后院、建筑用途、通行关系、坡度/落地等主题；这些主题沿用现有数据。主题切换不同时叠满所有线和颜色。

只装配属于同一条有效输入链的结果。上游尚未生成时显示实际已有范围；下游过期时允许查看旧结果，但使用灰色虚线和“旧结果”标记，不能拼接成貌似有效的新城市。

## 4. 观察尺度与显示密度

当前相机是正交相机，距焦点约 3400 米；分级依据投影大小和 `Camera.Size`，不使用相机距离作为近景判断。下表是初始调参范围，需按屏幕分辨率和对象大小校准。

| 观察级别 | 初始 Size | 模型与图层内容 | 标注 |
| --- | --- | --- | --- |
| 区域 | 1200–3600 米 | 核心、城外片区、主路、城墙、地标、田组；建筑保留屋顶轮廓 | 片区、城门、重要公共院区 |
| 街区 | 250–1200 米 | 主次路、街区边界、建筑排布、院落、公共空间 | 选中街区与少量重要道路；不铺满地块编号 |
| 街段 | 60–250 米 | 屋檐、楼层门窗、院门、围栏、台阶和市场简模 | 选中对象名称、入口、路宽及邻接关系 |
| 单体/节点 | 约 25–60 米 | 单体立面、共墙、基础、门前通道、路口接缝 | 真实尺寸、来源、局部问题 |

将滚轮最小观察范围由当前约 120 米降低到约 25 米，使普通缩放也能进入单体检查；保持正交沙盘操作。聚焦选中对象时依据其包围盒适配镜头，避免固定近景尺寸使大院区被裁掉。

细节启闭以像素大小为主，并设置滞回。远处门窗、细围栏不再逐件显示，但不能让城门开口、主入口和整座地标突然消失。文字保持屏幕尺寸，发生拥挤时减数量，不把字号无限缩小。

## 5. 统一视觉规范

### 实体外观

- 普通建筑采用暖灰墙、灰褐屋顶、较深门窗和墙脚；保留少量稳定色差，避免每栋随机一种高饱和颜色。
- 公共建筑以灰石墙、较深屋顶和清楚的入口/塔楼轮廓区别；保持与住宅同一套明暗、线宽和材质精度。
- 土路、院地、广场、后园各有可辨认的色相/粗糙度差异；细纹理保持克制，延续地形的去平铺处理。
- 轮廓优先依靠体块、接缝和光照。细描边用于选中对象或分析边界，不给全城所有三角形描黑边。

### 信息配色与线型

住宅使用灰绿，商住使用低饱和赭黄，作坊使用灰紫，公共用途使用蓝灰；这些语义在地块和建筑主题间保持一致。地块用途和建筑实际功能仍是两类数据，详情注明来源，不能因颜色近似而当作同一结论。

状态通过额外的轮廓与符号表达：悬停细浅边，选中琥珀色粗边及 ID，通行路径青色箭头，警告橙色三角，错误红叉，过期灰色虚线。用途填色保留，避免选中后整栋改色而丢失用途信息。

规划线宽初值：普通边界约 1–1.5 像素，重要边界约 2 像素，选中轮廓约 3 像素。颜色配合线型、符号与文字，灰度下仍能区分选中、错误和过期。

## 6. 各类对象的具体升级

### 6.1 区域、核心与城防

区域展示区分研究范围、建设片区、防御核心和实际宅地。远景以外轮廓和低透明填色表达，避免把未开发地与建成区涂成同一强度。区域入口 E 与城门 G 保持不同符号。

沿 `WallFootprint` 构建简化实体墙：连续墙身、清楚的墙顶和少量分段变化；沿地形分段接地。沿 `TownGate.Passage` 保留开口，门墩和门楼只能落在已有允许墙体范围，不侵入道路净宽。

现有城防数据是二维占地，没有工程墙高和门洞净高。首版可用统一的可调示意高度，例如墙高 6 米；选中时明确显示“示意高度”，不计入权威建筑高度或土方统计。墙顶、门楼细节受这一显示包络约束。

不为了圆滑外观移动城墙边界、缩窄城门或抹去真实拐角。独立角楼若超出现有墙体占地，必须先有规划数据支持；首版只细化已有轮廓。提供“隐藏城墙 / 低墙查看”选项，检查核心内部时保留墙脚线与门洞位置。

### 6.2 道路、路口与广场

使用 `RoadNetwork.Geometry.Area / Surfaces / Boundaries` 作为唯一平面依据。主路、街巷、路口和广场在默认实体模式下仍能分辨，但路口内部不再叠加独立端帽造成色块接缝。

土路加入轻微中心压实与路肩过渡；只在确有边缘结构的地面显示薄收边。保留中世纪街道的连续土路观感，避免全城自动长出现代路缘石、人行道和标线。

规划模式才显示中心线、拓扑节点、可临街边界及路口预留。远景过窄道路可附加最小像素宽度的符号线，以明确的“路网”主题展示；实体路面、面积和测量继续使用真实宽度。

地面渲染须统一贴合原始地形三角网格。当前环境采样与地形网格不同，不能仅靠整体抬高 0.12 米消除穿插；低角度专门检查路口、坡岸和院地接缝。渲染适配不改动道路坡度判断和规划高程。

### 6.3 街区、地块与后院

街区、地块、建筑带和后院使用不同层级的线。区域视角隐藏普通地块边界；街区视角显示边界但隐藏密集编号；选中地块时才完整显示其建筑带、后院、临街边和相关通道。

临街边使用有方向的短标记，后界保持细线。住宅后园、作坊院地、公共院场和未分配空地有稳定的简化地表，不将每个地块做成浮在地面上的彩色托盘。

空地需区分“尚未生成建筑”“保留院落”“细分剩余地”“建筑生成失败”。失败由已有问题数据驱动，不能把所有空白都标成错误。多个地块拼成的院落或共用通道应显示其共享关系。

### 6.4 普通建筑：细节加在结构上

保留 `BuildingMass` 的位置、占地、楼层、墙高、屋脊、门位、屋顶投影和共墙关系。

| 部位 | 简模细化内容 | 约束 |
| --- | --- | --- |
| 屋顶 | 檐口厚度、屋脊收口、山墙边，少量稳定色差 | 使用现有 `RoofProjection`；不能扩大悬挑挡住通道 |
| 墙身 | 清楚的墙脚和少量楼层分隔，转角可读 | 不增加假楼层，不以随机噪声改变整体高度 |
| 门 | 门框、浅凹进感、门槛，延续已有台阶 | 唯一主入口沿用 `Door / StreetPoint`，不能为好看随机换门位 |
| 窗 | 按实际楼层布置少量窗洞示意、窗框或窗板 | 不在共墙开窗；不穿门、不越墙、不排在不存在的楼层 |
| 共墙 | 接缝和两栋屋顶的高度关系 | 共墙仍属原数据，不显示成可通行的缝隙 |
| 基础 | 显示墙脚落地和台阶侧面，必要时补齐示意封边 | 不通过抬升整栋建筑掩盖地面高差问题 |

门窗首版可采用浅层几何和深色内面，无需真实室内。每面按可用宽度选择少量开间，不强行让短立面套入固定窗数。

普通住宅、商住、作坊通过窗门比例和已有空间的用途特征区分：商住强调底层入口，作坊强调已有院地与附属棚。新招牌、遮棚或屋顶小构件必须落在现有占地及高度包络内；无法容纳时省略，不挤入街道或主通道。

屋顶可单独隐藏，但首版只露出明确标为“占地/楼层示意”的平面，不凭空生成房间。降低邻近建筑显示高度时保留原始屋顶虚线，测量仍读取真实体量。

### 6.5 公共建筑与机构院区

教堂在已有主殿、可选塔楼上强化高窗、主入口、檐口和钟楼开口；`OpenHall` 主殿不按普通住宅画多层楼板/窗带。若生成结果省略塔楼，展示也必须省略，并保留原问题说明。

修道院沿现有 U 形翼部加强屋顶方向、连贯立面和中央院场边界；用院场铺地与入口关系解释组合，不在未预留位置补建回廊。其他院区按实际 `Program / PrecinctId` 选配外观，不能只因名字像公共建筑就新造一个体量。

远景优先保留已有地标轮廓，近景再增加入口和立面细节。公共院区的标注落在可见锚点，并用短引线避开屋顶和道路。

### 6.6 后院、市场和附属物

继续使用现有六类附属物，优先提升识别度：棚屋补门口和屋檐；摊位区分支柱、台面和布棚；水井保留井沿和井口；储物用少量箱/桶形轮廓变化；围栏具有连续杆件、转角和明确开口。

这些变化属于同一物件内部的外观变体，继承原对象 ID、占地、接近区和数量预算。避免每根杆、每个窗框都成为独立场景节点。

院门、摊位之间的公共通道、井边接近区和建筑门前区域，优先保持可读。围栏开口使用已生成的开口，不能为了视觉连续重新封起来。后院展示可用稀疏的已有物件和地表分区表现，不通过随意加满杂物来提高“细节”。

### 6.7 田园与城市边缘

沿已有 `Landscape.Shape / CultivationLines` 显示田组、耕作方向、田头和果园行列。远景把密集条带合并为方向性明暗，近景再出现浅垄沟；不再将全图田地画成高对比平行线。

果园可沿已有种植线使用统一简化树冠符号；草地保持开阔。田埂、灌木或树列需要服从边界与通道避让。自然植被仍复用原树位；精细林缘、草簇与芦苇与地形 D 阶段共用一套系统。

本项与地形方案 C（人工地面融合）合并实现，避免建立第二套路面材质、贴地采样和农田渲染。地形 D 的大规模自然植被细节可独立延后。

## 7. 查看、选择与诊断

### 选择和来源

默认单击选择，空白处取消；支持悬停高亮、聚焦选中对象、返回上一个视角和按编号查找。选择类型随主题设置为区域、道路、地块、建筑或附属物，避免建筑屋顶总是挡住对地块的选择。

小细节归属父对象：点窗框仍选中建筑，点围栏杆仍选中围栏。几何不可见时默认不接受命中；透视选择必须显式开启，并在界面标明。

详情保持一条清楚的来源链：片区 → 街区/地块 → 建筑 → 附属物；道路显示所属路段、路口及其边界来源。跨节点切换只保留版本兼容的选择，重生成后不能用相同数字 ID 自动指认一个不同对象。

### 通行与尺寸

选择建筑可高亮关联道路、门前走廊和通院路径；选择城门可高亮其关联入口及现有路网路径。通道线必须位于实际 `Corridor` 内；数据只有走廊多边形时，可在其中求展示路径，求不出则只高亮走廊，不能用穿过建筑的直线代替。

常用检查包括名义道路宽度、地块面宽/进深、建筑墙高/总高、楼层、门前净空与基础高差。参数宽度与现场截面测量分开标注；没有实际测量时只显示“参数宽度”。面积和长度来自原多边形/路径，不从屏幕线宽或简化模型反推。

高程详情显示对应的采样尺度；二维墙体的展示高度标为示意。通行高亮说明的是现有规划关系，不冒充已经生成的导航网格或人物可行走测试。

### 问题定位

把现有 `Issues / Notices / Warnings` 汇入可筛选清单：错误、警告、几何回退与可选构件省略分别显示。选择一项后定位到局部，并突出相关边界、入口或高差；同一区域密集问题在远景合并为带数量的标记。

普通检查保留深度遮挡。需要查重叠、共墙或通道时可隐藏屋顶、隐藏邻居、降低城墙或开启局部透视，避免全城长期透视造成误判。

### 面板与标注

进入城市节点后，左侧地形参数默认折叠为底图控制；右侧保留生成参数与对象详情，顶部提供查看模式、分析主题和常用定位。F9 沿用现有隐藏界面功能，可另设保留图例的检查截图。

标签采用屏幕布局与避让：选中对象、错误和城门优先，其次公共地标与片区，普通对象只在近景或选择后显示。以 1440 × 900 的默认窗口为准，区域视角先限制约 12–18 个常驻标签，近景约 30–40 个；拥挤时压缩数量。避免白色粗描边文字压住道路或互相覆盖。

## 8. 实现结构

建议新增一个展示装配层，读取六个节点当前有效的只读结果。它不成为第七个生成节点，不持有第二套布局算法。

| 设计时建议组件（当前落地情况见实施文档） | 职责与接入点 |
| --- | --- |
| `CityVisualSettings` / `configs/city_visual.tres` | 简模外观、分析色表、细节档位、标注密度和城防示意尺寸 |
| `CityViewState` / `CityPresentation` | 查看模式、主题、可见性、选择、版本检查与上下文装配；接入各 `Main.*` 页面 |
| `CityGroundRenderer` | 复用定型道路和 `GroundPatches`；与地形 C 共用贴地与材质规则 |
| `BuildingDetailBuilder` | 从 `BuildingMass / Access / SharedWalls` 派生外观；建筑节点和最终场景共用，避免两套模型 |
| `FortificationPreviewBuilder` | 从 `WallFootprint / Gates` 生成示意墙体、门洞和查看用低墙版本 |
| `CityOverlayRenderer` / `CityLabelManager` | 层级线条、局部选择、路径、标签避让与屏幕尺度 |
| `CityPickIndex` | 基于包围盒的候选筛选与精确命中，保留父对象/部位来源 |

缓存键包含输入节点及其版本、外观版本和细节级别；选择身份包含对象类型、来源版本和 ID。切层复用几何，改变选择只更新小范围高亮，不重新生成全城网格。

当前 `BuildingPreview` 与 `SceneMeshes.Buildings` 均调用 `BuildingMeshBuilder`，应在这一共用路径加入细节。合批后保留面到对象的映射，避免增加模型精度后失去来源追溯。场景现有的逐三角形拾取需先做空间筛选，再精确求交。

实体几何正常参与深度测试。规划覆盖与透视覆盖分别装配，不统一关闭深度测试；尺寸线优先使用屏幕覆盖，避免靠抬高几米的世界几何保证可见。边线可用有实际宽度的三角带或屏幕线条，不依赖单像素线在所有缩放下都清楚。

## 9. 性能与验收目标

先采集**当前完整城镇**的基线。此前地形报告的 0.x ms 指标是自然地形场景，不能当作含建筑、附属物、标注和拾取的新基线。

建议首轮几何预算为普通建筑近景约 250–800 三角形/栋、公共体量约 1000–3000 三角形/个、小附属物约 30–180 三角形/件。具体数字以可见特征决定，不能为了达到数量而堆面；全城远景使用简化网格，门窗与细围栏在近景启用。

按空间区块和少量共享材质合批。屋脊、门窗和杆件避免一件一个 Node；小构件默认不单独投影。屏幕标签复用并只更新可见内容，鼠标悬停不能重建全城。

待测目标：1440 × 900 标准档的中位数与 P95 帧耗时相对完整城镇基线增幅控制在约 25% 内；基线满足 60 FPS 时继续以 P95 不超过 16.7 ms 为目标。选中/主题切换的可见反馈目标小于 50 ms；额外常驻显存首轮预算 128 MiB。所有目标需同机同镜头验证，不视为当前测量结果。

每阶段固定截图至少包含全城斜视、全城俯视、城门内外、复杂路口、密集街屋、独立后院、市场、教堂、修道院和田园边缘，并检查正午式中性光照及常用低角度。记录种子、节点版本、查看模式、主题、质量档位、相机和选择对象。

验收必须确认：

- 仅改展示参数时六个节点结果、统计和原始环境指纹不变。
- 屋顶、门窗、围栏细节不越过允许包络；门洞、通道、共墙、保护区和院门关系正确。
- 道路、广场、院地与基础在坡面不出现明显漂浮、穿插和闪烁；保留真实高差问题供诊断。
- 全城和近景都能辨认主次关系；同一语义跨节点一致，普通标签不遮住被选中目标。
- 拾取与显示对象一致，状态过期后不错误保留选择或混入新结果。
- 反复切层、缩放、选择、重建后资源占用稳定；细节与标签不随相机跳变或游动。
- 1440 × 900 和 1280 × 720 下查看工具、图例与详情可用，支持折叠面板及 F9 展示。

现有 `test`、`test-road-geometry-ui`、`test-building-ui`、`test-placement-ui` 继续回归；在实施时增加城市展示截图、细节包络、来源映射与交互性能检查。数据测试不能代替截图和运动观察。

## 10. 推荐实施顺序

| 阶段 | 交付重点 | 直观完成标准 |
| --- | --- | --- |
| **V1：展示规范与查看框架** | 三模式、统一色表/线型、基础标签、面板折叠、近景缩放、只读装配与缓存 | 全城布局清楚，各节点切换语义一致，旧结果明确 |
| **V2：道路与城市地面** | 贴地、主次路/路口/广场、地块与后院层级；并入地形 C 的人工地面部分 | 街区与院地不再像浮动色块，路口和临街边容易判断 |
| **V3：建筑、城墙与公共地标** | 屋檐、门窗、墙脚、共墙、门洞、示意城防及公共体量细节 | 能从近景直接读懂街屋、城门与院区空间关系 |
| **V4：院落、市场与田园** | 现有附属简模细化、开口和接近区、耕作条带与果园行列 | 院落用途和通道更清楚，田园与城镇边缘连贯 |
| **V5：检查工具与整体收尾** | 深入来源联动、尺寸检查、问题列表、局部透视、性能与多尺度验收 | 查看问题无需在多个面板中猜测，生成结果与展示一致 |

V1 先建立必要的选择与标注能力，V5 再补齐深入检查工具；可读性、包络验证和性能检查贯穿每阶段。

**建议第一轮交付 V1–V3。** 这会同时改善整体布局、城市地面和主要简模体块，形成可以直观检查的新演示场景；随后 V4–V5 完善院落活动空间和精细检查。
