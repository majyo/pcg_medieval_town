# 可视化与调控界面改造 · 方案

> 状态：第 1 步（说明文字）已完成。之后方向调整为**以节点图为核心**（见 §0）：节点图、点节点只看它的输出、每个键的画法已经实现，取代了 §3、§4 的检视 / 成果模式和面板重组；§6 分析画面、§7 前后对比、§10 第 7 步清理仍未实施。基于节点图架构（[ARCHITECTURE.md](ARCHITECTURE.md) §2）。与城市规划阶段（[CITY_PLANNING.md](CITY_PLANNING.md)）互不阻塞；城镇生长的新键直接按本方案登记画法，它的 §5、§7 届时按本方案改写。

## 0. 现状：节点图

- **底部节点图**（`ui/NodeGraph.cs`）取代左侧阶段列表：每个阶段一列，每个节点一个方块和状态点，连线是读写关系。悬停或选中一个节点时，它的上游标成蓝色、下游标成橙色。
- **点节点只看它的输出**：`GraphFocus` 是唯一的显示状态。`Main.FocusOutputs` 按节点取它写出的版本（`CityGraph.Output`），编辑型节点另取读到的版本（`CityGraph.Input`）；能画在地面上的交给 `FieldStyles`，其余交给 `CityView.Show`。点阶段标题看整个阶段的输出，点空白处回到完整城镇（按“视图”页设置）。有焦点时隐藏树木和地被。
- **每个键都有画法**：新增采样网格（棋盘格）、场地（过渡格式）、通行区的地面着色，以及城址（规划半径圈）、道路连线（编辑型节点只把新加的连线标彩色）的叠加画法；区域格局拆成渡口、过境道路、起源点，“广场与城墙”拆成广场、城墙、城门，各自独立显示。渡口和起源点在检视时加地面圆圈，城门加连向图边入口的细线。道路三个等级改用三种色相，“易淹”改成青绿色。
- **删除**：联动视图、显示到此阶段、阶段页的“可视化”区、“场地限制”图层（与可建设判定着色重复）、地形页里重复的种子和“重建地图”。
- **卡片**：“读 / 写”的每个键可点击，读的键跳到写它的上游节点并显示该键；节点写出多个场时，点哪个就在地面上画哪个。卡片上多了“显示”按钮，选中的卡片有描边。
- **截图**：`capture` 为每个节点多存一张只显示其输出的 `node_NN_<节点类名>.png`（场地和区域节点为全图俯视，城镇节点为城镇近景）。

## 1. 目标与范围

界面要回答三个问题：**这一步读了什么、做了什么决定、写出了什么。** 用户点任意一个节点，都能在画面上直接看到这三样东西，图例和面板说的就是画面上的东西。

原则：

- **可视化的单位是键，不是阶段或图层。** 节点只通过键交换数据（ARCHITECTURE §2），所以“这一步做了什么”就是“它写出的键长什么样”。每个键登记一种画法；换掉一个节点，只要它写同样的键，画法照用。
- **显示状态只有一个来源。** 画面、图例、“正在显示”提示、面板上的开关都从同一个 `ViewState` 推出来，不再有几张手写的表互相对不上。
- **分析画面和成果画面分开。** 看数据时颜色要和图例一致，不受雾、卡通分阶和曝光影响；看成果时才用完整的画风和大气。
- **界面上的每个名词都有一句解释。** 节点、参数、键都带说明，鼠标悬停可见。

范围之内：键的画法登记表、检视 / 成果两种模式、节点聚焦、面板重组、缺失的可视化、分析配色与光照、参数改动前后对比、遗留和重复项的清理。

明确不做：

- 不改任何节点的生成算法（第 7 步的种子语义改动除外，单独决定，见 §9）。
- 不做正交相机。场景保持透视；分析模式也只是换光照，不换投影。
- 不做节点图的连线编辑器（拖线、增删节点）。节点顺序和连线仍写在 `TownGraph.Create` 里。
- 不改“环境”页参数本身的内容，只调整它所在的位置。

## 3. 显示模型

### 3.1 键的画法（`rendering/KeyViews.cs`）

每个键登记一个 `KeyView`，取代 `CityLayer`、`CityView` 里的各个 `Build*` 方法和 `FieldStyles`：

```csharp
public abstract class KeyView
{
    public abstract IKey Key { get; }
    public abstract ViewKind Kind { get; }            // Ground：画在地面颜色图上（标量场、分类场）；Overlay：网格叠加
    public abstract LegendEntry? Legend(object value, Emphasis emphasis);
    public virtual string? Describe(object value, Vector2 p) => null;   // 探针读数
    // Overlay 才有：画出这个值；previous 是同一个键在上游的版本（编辑型节点用来突出新增部分）
    public virtual void Build(Node3D root, object value, object? previous, Emphasis emphasis, ViewContext context) { }
}

public enum Emphasis { Focus, Context, Result }    // 聚焦节点的输出 / 输入作为背景 / 成果画面
```

- **`Focus`**：饱和色，线宽按屏幕像素算（不随距离变细），标注清楚。
- **`Context`**：同样的几何，降饱和、半透明，作为背景，不抢视线。
- **`Result`**：成果画面里的样子（实体城墙、房屋、铺装路面）。在成果画面里不该出现的键（各种场、通行区、连线）没有 `Result` 画法，不显示。

`FieldStyle` / `CategoryStyle` 原样并入，成为 `Kind = Ground` 的 `KeyView`。`CityView` 改为 `KeyLayers`：为每个正在显示的（键, 写入它的节点, 强调方式）保留一个 `Node3D`，按值的引用判断是否需要重建，沿用现在 `Update` 的做法。

**不变量**：`Keys` 里的每个键都有登记的画法（`site` 这类过渡键可登记为“隐藏”）。检查放在 `Main` 的 `--test` 路径里（`city` 不能引用 `rendering`），跟 `TerrainChecks`、`Checks` 一起跑。

### 3.2 按节点取值（`CityGraph`）

新增：

```csharp
public object? Value(int node, IKey key);   // 节点 node 写出（或编辑后）的版本；未生效时为 null
public object? Input(int node, IKey key);   // 节点 node 读到的版本，即 Sources(node)[key] 写出的版本
```

`Value` 现在是私有的，改成公开即可。编辑型节点的检视画面同时拿到 `Input` 和 `Value`，`KeyView.Build` 的 `previous` 参数由此而来。

### 3.3 显示状态（`ViewState`，放在 `Main`）

```
ViewState
  Mode      检视 | 成果
  Focus     无 | 阶段 s | 节点 n
  Ground    地表 | 某个场的键（及写入它的节点）
  Pinned    用户固定显示的叠加键（集合）
```

画面、图例、“正在显示”提示条、面板上所有开关都由它推出，改哪里都只改这一个对象。替代 `_ground`、`_layers`、`_linkView`、`Views`、`StageVisualization`、`ShowStageView`。

**检视模式**下，聚焦节点 n 时自动推出：

| 内容 | 规则 |
| --- | --- |
| 叠加（Focus） | n 写出和编辑的所有 Overlay 键 |
| 叠加（Context） | n 读入的所有 Overlay 键 |
| 地面 | n 写出的第一个场；没有就用 n 的 `Backdrop`（见下）；再没有就用 n 读入的最后一个场；都没有就是地表 |
| 其余 | 隐藏，`Pinned` 里的照常显示（Context） |

`CityNode` 新增可选的 `public virtual IKey? Backdrop => null`，给规则选不准的节点指定底图，例如“起源点”指定 `region.origin_score`（§5），“通行区”指定 `road.zones`。

聚焦阶段 s 等于把 s 里所有节点的叠加取并集；地面取 s 里最后一个写出场的节点的那个场。

**成果模式**：地表 + 所有有 `Result` 画法的键 + 森林、河面、地被 + 完整大气。`Pinned` 照常叠加，用来在成果上临时看一层数据。

画面上始终有一条“正在显示”提示（放在图例顶部），例如：

> 检视 · **起源点** · 底图 起源点得分 · 输出 起源点、城址 · 输入 过境道路、渡口

图例只列这条提示里出现的键，由同一个 `ViewState` 生成，所以永远和画面一致。

## 4. 界面布局

```
┌ 顶栏：种子 随机 重建地图 │ 生成 取消 自动 进度 │ [检视|成果] │ 全图 俯视 城镇 │ 面板 ┐
├ 左：流程 ──────┬──────── 3D 视图 ────────────────┬ 右：节点 | 图层 | 外观 ┤
│ 阶段 → 节点    │                                 │                       │
│ 点 = 聚焦      │  左下：指北针 + 正在显示 + 图例  │                       │
├────────────────┴── 状态栏：聚焦节点相关的读数 ─────┴───────────────────────┤
```

- **顶栏**：新增“检视 / 成果”切换（快捷键 V）。地图种子只留在这里。
- **左侧流程**：结构不变（阶段 → 节点、状态灯、耗时）。点节点 = 聚焦该节点并切到检视模式；点阶段 = 聚焦阶段；再点一次已聚焦的项 = 取消聚焦。过渡用的节点显示为灰色斜体，悬停提示“过渡用，计划删除”。耗时改为悬停或右侧卡片里显示，列表里只留状态灯，减少噪声。
- **右侧“节点”页**（取代“阶段”页）：
  - 聚焦节点时只显示这一张卡片。卡片依次是：标题与状态 → 一句话说明（`Description`）→ **读 / 写列表**（每个键一行：状态、标签、单位、“着色”或“显示”按钮，点击把它设为底图或固定叠加）→ 摘要与提示 → 参数（每行悬停显示 `Hint`）→ 重跑、默认、对比上次（§7）。
  - 聚焦阶段时列出该阶段的所有卡片，和现在一样。
  - 未聚焦时显示流程总览：每个阶段一行摘要和状态。
  - “地形”阶段的卡片只放地图参数（起伏、河宽、森林密度、树木间距），种子和“重建地图”不再重复。
- **右侧“图层”页**（取代“视图”页）：按阶段分组列出全部键，每行：状态灯、标签、“着色”单选（场）或“固定”复选（叠加）。这是 `ViewState.Ground` 和 `Pinned` 的完整编辑器，不再有手挑的子集。等高线作为 `site.height` 的一种叠加画法，等高距是它的显示参数，放在这一行的展开项里。
- **右侧“外观”页**（取代“环境”页）：森林、河面、地被与岩石的开关，相机视野，以及现有的大气预设和参数。只影响成果模式（§6）。
- **状态栏读数**：先列聚焦节点的输出，再列输入，其余省略；未聚焦时列底图的场和可建设判定。按住 Alt 显示全部。
- **删掉**：“联动视图”、“显示到此阶段”、阶段页的“可视化”区、`CityLayer.Site` 图层（与可建设判定着色重复）、地形页里的种子和“重建地图”、阶段页和建筑页里重复的“森林”开关。
- **启动状态**：成果模式，不聚焦，右侧显示流程总览。

## 6. 分析画面

- **大气覆盖**：检视模式下 `Atmosphere` 应用一组固定覆盖值：关雾、关 SSAO、关泛光、曝光 1、饱和度和对比度 1、`style_*` 回到中性（不分阶、不着暗部色调）。太阳固定在高角度（约 55°），只保留柔和的明暗来显示起伏。切回成果模式时恢复“外观”页的设置，不改动用户的值。
- **地面着色**：`ground.gdshader` 在 `view_mode = 1` 时，颜色走 `EMISSION`，用 `analysis_shade`（默认 0.25）控制叠加多少地形明暗。目标是平地上屏幕颜色和图例色带的差 ΔE 小于 3。
- **配色**：
  - 道路三种等级改成色相明显不同的三色，并按等级给 Focus 线宽（如主街 4 px、城外 3 px、街巷 2 px）。
  - 不可建设原因：水域深蓝，易淹换成青绿，河岸退让改为浅蓝加斜线纹理，坡度过大红褐，森林深绿；可建设留作最浅的底色。
  - 所有分类配色用 dataviz 的校验脚本检查色觉缺陷下仍可区分。
- **Context 样式**：统一为原色降饱和 70%、不透明度 45%，所有叠加共用，不在各画法里各自定义。

## 7. 改动前后对比

- 参数改动让节点过期时，`ViewState` 记下聚焦节点所有输出的旧值（只保留引用，存下来的值本来就不可修改，不需要复制）。
- 重跑完成后，节点卡片显示摘要的前后对比，例如“180 栋 → 192 栋”“城墙 1,240 m → 1,310 m”。
- 卡片上的“对比上次”开关：叠加类的键把旧版本以虚线 Context 样式画在下面；场则在“新 − 旧”的差值图和新值之间切换，差值图用发散色带。
- 只保留最近一次的旧值，切换聚焦或重建地图时清空。

- `ParamAttribute` 新增命名参数 `Hint`：这个参数控制什么，往哪边调会怎样。例如：“超坡惩罚：坡度超过免费坡度后，超出部分的平方乘以这个系数加到代价上；调大后路线更绕、更平。”
- `Key` 新增可选的 `Description`，在“图层”页和读 / 写列表里悬停显示。
- **不变量**（写进 `Checks` 的节点图检查）：每个节点都有非空说明，每个节点参数都有 `Hint`。大气参数的 `Hint` 不强制。

## 9. 待定问题

- **节点种子的语义。** 建议把 7 个节点的“种子”改名为“变体”，默认 0，实际种子 = 哈希(地图种子, 节点名, 变体)。这样“随机”换地图种子时，城镇的随机选择也会跟着变；想在同一张地图上换一种城墙形状，就调“变体”。这会改变三个种子的现有结果（检查只要求两次生成一致，不受影响），所以单独作为第 7 步，需要确认后再做。
- **成果模式里是否允许把地面着色和房屋叠在一起。** 方案允许：在“图层”页把某个场设为底图即可，提示条会写明。
- **检视模式进入时是否自动调整相机。** 方案不自动移动相机，以免画面跳动；只在“正在显示”提示条上给一个“取景”按钮，框住聚焦节点输出的范围。
- **城镇生长的“显示到第 N 期”**（CITY_PLANNING §5.1）成为 `town.growth` 画法的显示参数，放在“图层”页这一行的展开项里，不再是阶段页的专用控件。
