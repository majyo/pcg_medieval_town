> 状态：第 9 步（街巷体系，§11）全部完成；第 10 步（地块与后院，§12）全部完成。第 11 步（地形修整，§13）全部完成，地面已改为全局求解（§13.11）；重做为“先台地、后地块”的方案见 §14，已完成。接在城市规划阶段（[CITY_PLANNING.md](CITY_PLANNING.md)，第 1–8 步）之后，步号接着编为第 9–14 步。每一步动手之前，先在三个种子上量现状，再把这一步的详细设计补进本文（与 CITY_PLANNING §13、§14 的做法相同）。

## 1. 目标与范围

城市规划阶段回答了“城在哪、多大、怎么长成的”：城墙、城门、骨架道路、地标、全图每一格的用途都已经定下。这一阶段回答**每一片区域内部是怎么组织的**：

- 街巷怎么分级，哪些是穿城的街，哪些是后巷；
- 地怎么切，长条地块、街角地块、客栈大院，后院里有什么；
- 地面怎么整平，道路的纵断面、广场、台地、桥；
- 房子是什么类型，商住楼、街角房、客栈、城外小屋、窑和水车房；
- 城墙和地标内部是什么样子，塔楼、城门楼、壕沟、墓园、回廊、城堡内院；
- 城外的田怎么分，条田、葡萄园行列、果园、树篱。

成果的精度停在**可检查的数据加体块造型**：每个元素有位置、尺寸、类型，能单独显示、单独检查；建筑做到体块、屋顶形式和出挑。材质、门窗、整体风格统一属于之后的视觉阶段。

讨论时定下的三点：

1. **街巷形态按分期混合**：一、二期（村落、市镇）是沿过境道路自然长出来的，保留现在的有机街巷网；三期填充和四期城外团块是有了城墙、有了领主或市镇规划之后成片开发的，改为“主街 + 垂直于街的长条地块 + 地块尾端的后巷”的规划式格局。这样城市有历史层次：老城弯曲，新区规整。
2. **地形修整放在这个阶段**：建筑的基座、台阶、挡土墙、桥的引桥都依赖整平后的高度，放到视觉阶段会让建筑类型做两遍。
3. **城外田野的布局放在这个阶段**：条田的走向、田块边界、树篱、田间小路是规划数据；地面纹理（犁沟、葡萄行的颜色）属于视觉阶段，按这里的数据取样。

明确不做：

- 材质、门窗、招牌、街道小品的细部，风格统一（视觉阶段）。
- 室内。
- 人口、经济或智能体模拟。“规划式”只是几何规则，不模拟谁在规划。
- 复杂水文：壕沟、水磨的引水渠只做几何；壕沟默认是干沟（见 §9）。
- 多座城镇、城外村庄和独立农庄（CITY_PLANNING §9）。
- 不改地形生成和 `ITerrain` 接口；整平是叠加上去的（§4.3）。

## 3. 原则

- **沿用前一阶段的做法**：先广后深；每一步拆成 a、b、c 小步，每一小步结束时三个种子都能跑完、契约全过、截图可看；每个新功能附带一条契约；节点按“一个可单独替换或调参的决策”划分，反复使用的算法放进 `tools/`。
- **顺序是 街 → 地 → 地面 → 房**：后面的步骤只读前面的键，不回头改。唯一的例外是整平：它读街巷、广场和地块，写一个叠加高度，之后的建筑、地标、城防按整平后的高度放。
- **规划判断用原地形，造型用整平后的地形**：采样、评价、选址、生长、街巷都继续读 `site.height`，整平是“按规划修地面”的结果，不反过来影响规划。
- **分期决定形态**：节点按 `town.growth` 的分期区分有机区和规划区，规则写在节点里，分期之间的界线可以由参数调整（例如“哪几期按规划式”）。
- **每个新元素都可以关掉**：与地标一样，新节点有“有无”或强度参数，关掉时节点照常运行、下游不受影响，便于对比和定位问题。
- **数据是二维加高度**：街巷、地块、院落、田块仍是平面多边形和折线；高度只在整平（叠加场）和建筑（基座、檐口、屋脊）里出现。

### 4.3 第 11 步：地形修整

新分组“地形修整”，排在“街区与地块”之后、“建筑”之前。

**数据**：新键 `grading`（`GradePlan`）。它不是一张全图高度，而是一组带目标高度的形状：道路走廊（折线、每个顶点的高度、宽度、两侧放坡）、平台（多边形、高度）、挡土墙（折线、上下高度）。按需求值：任一点的整平高度 = 覆盖它的形状按优先级给出的高度，放坡带里与原地形混合，形状以外就是原地形。

**和地面的衔接**：`Main` 把 `grading` 叠加到地形上，交给地面绘制（Terrain3D 的高度图按 1 m 网格导入，只重导受影响的区域）和城市绘制（`CityView` 的 `Height`）。`ITerrain` 不变：`Main` 用一个包装（例如 `GradedTerrain`，实现同一个接口）把原地形和叠加场合起来；采样和规划节点仍读原地形。

| 半步 | 内容 |
| --- | --- |
| 11a 道路纵断面 | 新节点 `RoadProfiles` 道路纵断面：每条路沿中线取原地形高度，平滑成坡度不超过按等级给定上限的纵断面（主街 6%、次街 8%、巷 12%，超过时巷允许做台阶，标记出来给画法），横向取平，两侧按 1:1.5 放坡；路口取各条路的共同高度。 |
| 11b 广场与台地 | 新节点 `Platforms` 平台：同时把城防、田野记下的壕沟、引水渠、葡萄园台地整平进来（第 13、14 步之前这部分为空）。市场、小广场整成平面（留不超过 2% 的排水坡），地标用地整成一块或几块台地（城堡保留在高处），每块地块临街进深内按街的高度做一个平台，后院顺着地形；平台与周围的高差超过 1 m 时记一道挡土墙。 |
| 11c 桥 | 新节点 `Bridges` 桥（写新键 `bridges`，同时往 `grading` 加引道）：使用中的渡口按两岸高度和净空定桥面高度，按河宽和跨度放桥墩，两岸的引道接进道路纵断面。现在的桥面板画法由它取代。 |

验收：三个种子上道路最大坡度（按等级）、挖填量（最大深度和总方量）、挡土墙总长；截图上街和广场是平的，坡地上的房子坐在台阶状的平台上。契约：纵断面坡度不超过上限（台阶段除外）；广场、平台高差在容差内；整平只在城镇和道路周围（离任何道路、地块、地标一个范围以外，叠加量为 0）；水面上只有桥墩和引道；挖填深度超过上限时给提示。

### 4.4 第 12 步：建筑类型

`GableHouses` 换成按类型选型的 `Houses`；`Building` 加类型、由几个体块组成（L 形是两块）、屋顶形式（双坡、四坡、单坡）、出挑（每层伸出街面多少）、两侧是否共墙。

| 半步 | 内容 |
| --- | --- |
| 12a 类型与选型 | 按地块类型、用途、所临街的等级选型：市场核心和主街上是山墙朝街、逐层出挑的商住楼；居住区是檐口朝街的连排房；街角地块是 L 形街角房；大院地块是客栈（临街楼带车马门，院子另一侧马厩）；城外是低矮的独栋小屋；作坊地块仍是棚屋（12b 细分）。后院的后屋（第 10 步定位）在这里做成单坡小屋。 |
| 12b 作坊专用 | 火作坊里有窑（圆形或方形炉体加烟囱）、铁匠铺；湿作坊里有晒布架（成排的木架）、浸池；水磨有水车房，水轮朝河。 |
| 12c 连排与街廓 | 核心区和居住区的房子两侧共墙、连成一排，相邻两栋檐口高差不超过一层；房屋高度与街宽的比例有上限（窄巷边不建四层）；出挑不越过街宽的一个比例。 |

验收：各类型的栋数；连排比例（核心区应接近全部）；截图上主街是连续的街墙，城外是零散的小屋。契约：建筑在地块内（出挑部分可以伸到街面上方但不压对面）；共墙的两栋真的贴在一起；客栈只在大院地块上；窑和水车房只在对应的作坊或水磨用地上；基座高度等于整平后的平台高度。

### 4.6 第 14 步：城外田野

田野的节点排在用地分区分组里 `Countryside` 之后（分组改名为“用地与田野”）。田间小路是田野自己的数据（土路，画成细线），不进路网；田块避开过境道路格和作坊、地标的格。新键 `fields`（田块：多边形、类型、走向；边界：类型；小路：折线；另记要整平的葡萄园台地和引水渠）。

| 半步 | 内容 |
| --- | --- |
| 14a 耕地条田 | 新节点 `StripFields` 条田：每片耕地按坡向分成几个田区，每个田区里切成平行的长条（宽 10–20 m、长 150–250 m，走向顺着等高线，平地上垂直于最近的道路），田区之间留地头（犁掉头的空地）和小路；条田之间不设树篱（敞田制）。 |
| 14b 其他农业用地 | 新节点 `Enclosures` 圈地：葡萄园按等高线排行（坡陡时记台地，交给整平）；果园是规则的树阵（树的位置经 `Main` 交给植被，取代那里的随机树）；草场沿河不分块；牧场用树篱或石墙围成不规则的大块；林地边缘不动。 |
| 14c 引水渠 | 新节点 `MillRaces` 引水渠：每处水磨从上游一段距离引一条渠到水车房再回到河里，渠记在 `fields`，由 `Platforms` 整平成窄沟，水面按河的水位画。可以不做（见 §9）。 |

验收：条田的平均宽、长和走向与坡向的夹角；树篱总长；截图上城外有明显的条田纹理和围起来的牧场。契约：田块不压道路、作坊、地标；条田走向与等高线的夹角在范围内；树篱都在牧场或圈地的边界上。

## 6. 分组与界面

分组顺序变为：

地形 → 场地采样 → 场地评价 → 区域格局 → 城镇生长 → 用地与田野 → 路网 → 街区与地块 → **地形修整** → 建筑

共十个阶段，数字键 1–9 不够用，第十个用 0 键（`MainInterface` 里改快捷键表）。新节点在各分组里的位置：

| 分组 | 新节点（按顺序插入的位置） |
| --- | --- |
| 城镇生长 | `TownDefenses`（`RouteGates` 之后） |
| 用地与田野 | `StripFields`、`Enclosures`、`MillRaces`（`Countryside` 之后） |
| 路网 | `PlannedStreets`（`StreetMesh` 之前）、`WallLane`（`StreetMesh` 之后）、`Squares`、`StreetRanks`（`LandmarkAccess` 之后，`ExtractRoads` 之前） |
| 街区与地块 | `ParcelKinds`、`Wells`（`FrontageParcels` 之后） |
| 地形修整 | `RoadProfiles`、`Platforms`、`Bridges` |
| 建筑 | `Houses`（取代 `GableHouses`）、`Yards`、各地标布局节点 |

`Squares` 写的是铺装区，还要给离路远的前庭修一段连接的路，所以在“路网”里、`StreetRanks` 之前；`ExtractRoads` 把广场并进 `roads` 的铺装区，`StreetBlocks` 照常扣掉铺装区，不用另读广场。

## 8. 契约（汇总）

各步的契约见 §4，这里按键汇总。详细设计时细化，与前一阶段一样挂在约束的键上。

| 键 | 检查 |
| --- | --- |
| `road.links`、`roads` | 次街不在尽头树里；道路铺装不压墙线（城门处除外）；`road.plan` 的平行街离引导线的距离与它的偏移相符（§11.6） |
| `road.squares` | 在可建设格上，不压地标；每座城门有门内广场 |
| `parcels` | 街角地块的侧边贴着另一条路；作坊用途和作坊类型一致；大院地块离城门或市场在范围内、面宽 16–26 m |
| `yards`、`fixtures` | 院墙不压道路和房屋；水井在铺装区上；每个建成格离水源不超过上限 |
| `grading`、`bridges` | 纵断面坡度不超过按等级的上限（台阶段除外）；广场、平台高差在容差内；城镇和道路范围以外叠加量为 0；水面上只有桥墩和引道 |
| `buildings` | 在地块内（出挑除外）；共墙的两栋贴合；类型只出现在允许的地块上；基座等于平台高度 |
| `town.defenses` | 塔楼在墙线上、间距在范围内；城门楼跨在城门道路上；壕沟在城外、不压道路 |
| `town.layouts` | 子部件在用地内、互不重叠 |
| `fields` | 不压道路、作坊、地标；条田走向与等高线的夹角在范围内 |

节点图检查照旧：过期按依赖传播（例如让“道路纵断面”过期后，地块不受影响，建筑过期），两次生成一致。每一步都会改变下游的指纹，三个种子的数字按步记进结果。

## 10. 风险与待定

- **规划式街巷在坡地上**：严格平行的街在起伏的地上会切过陡坡。平行街只走通行区里的格，过不去的地方断开，留给 `StreetMesh` 补（§11.8）。
- ~~**街巷分级的标准**~~：已在三个种子上量过，“锚点之间最短路经过的次数”分不开（7 的城内街巷一段都没被经过），改用“尽头树”（§11.1、§11.3）。
- **整平的耗时和一致性**：Terrain3D 按 1 m 导入，每次重新生成都重导城镇范围的高度图，可能要几十毫秒到几百毫秒；只重导叠加量变化的区域。所有画城市的地方都要改读整平后的高度，漏了一处就会有东西浮在空中或埋在地下，所以 `GradedTerrain` 要成为 `CityView` 唯一的高度来源。
- **整平与植被、地被**：挖填后的地面上不应该留原来的树和地被。现有的城镇范围已经排除了它们，整平范围要并进去。
- **建筑数量和网格大小**：多体块、出挑、后屋、院墙会让城市网格的三角形数成倍增加。`MeshKit` 已按材质合并，必要时再按街区分块。
- **指纹和随机变化**：每一步都改下游，街巷网换随机种子时房屋数会差 ±25 栋左右（8b 时量的），比较结果时要区分规则的变化和随机的变化。
- **壕沟是干沟还是水沟**：默认干沟（不做水文）；靠近河的一段可以按河的水位画一层水面，作为可选项，13a 时再定。
- **客栈和大院的数量**：每座城门附近一到两处、市场边一处是否合适，10a 时在截图上看。
- **出挑的尺度**：每层伸出 0.3–0.6 m 在全图视角看不出来，只在近景有意义；如果近景截图看不出差别，12a 可以先不做出挑。

## 11. 第 9 步详细设计：街巷体系

### 11.1 现状

三个种子（73129 / 7 / 22017）上量了几样相关的数：

- **长度**：主街 901 / 456 / 611 m，城外道路 3.3 / 3.4 / 3.6 km，城内街巷 1362 / 1312 / 1504 m，城外巷道 953 / 1050 / 945 m，便道 2.0 / 1.6 / 2.2 km。城内街巷一段的长度中位数 52 / 59 / 68 m，最长 249 / 197 / 211 m。
- **尽头树**：反复剪掉只连着一条路的端点（城门、市场、图边入口除外），被剪掉的街巷占 24% / 58% / 36%（566 / 1367 / 881 m）。这些是只通向一片地的尽头路和它的分叉。
- **“经过次数”分不开**：在城内的城门、市场、主街与街巷的交汇点（11–16 个）两两之间求最短路，数每段街巷被经过几次。7 的城内街巷一段都没被经过，22017 只有 121 m 被经过：最短路几乎总走主街。所以分级不用介数，用尽头树。
- **三期在哪里**：城内三期 2.2 / 3.5 / 3.7 ha。按离主街和城外道路的距离，三期的格 0% 在 20 m 以内，9% / 0% / 0% 在 20–45 m，50% / 18% / 14% 在 45–70 m，其余更远（7、22017 有 25% / 44% 超过 120 m）。一、二期的格 87–97% 在 45 m 以内。也就是说，主街两侧约 45 m 已经是一、二期的地，三期是长臂之间的楔形地，离主街 45–150 m。
- **四期**（城外）2.8 / 3.0 / 3.2 ha：离城外道路 20 m 以内 10–12%，20–45 m 32–43%，45–70 m 30–44%，70–120 m 4–15%。
- **街区太大**：城内街区 17 / 11 / 14 块，中位数 2764 / 2823 / 4155 m²，最大的 1.2 / 3.0 / 2.1 ha。
- **地块深度**：一、二期的地块平均面宽 9.4–9.8 m、进深 26–29 m；三期面宽 8.3–8.9 m、进深 31–36 m；四期面宽 13–13.5 m、进深 23–24 m。
- **墙根**：城墙内侧有路（16 m 以内，城门两侧 20 m 不算）的墙段只占 28% / 19% / 31%。城墙空地 0.60 / 0.71 / 0.64 ha，离墙 30 m 以内没建成的地 0.96 / 1.09 / 0.97 ha。
- **城门**：城门 20 m 以内的铺装 240–367 m²，相当于一条主街穿过，没有放宽。
- **地标门前**：教堂西端（门）离最近的路 16 / 21 / 35 m；城堡、修道院用地背面离路 2–26 m（地标通路只修到朝向市场的一边）。

### 11.2 原则

- **只加路，不改骨架**：主街、城外道路（过境道路）不动；新节点都编辑 `road.links`，只加街巷、巷和便道。
- **等级只往下调**：`StreetRanks` 只把街巷降为巷，不把任何路升级。墙根巷一开始就是巷。
- **规划区在格上划定**：规划街巷占到的格记进 `road.plan`，之后的有机街巷（`StreetMesh`、`SuburbLanes`）不在那里撒点、不从那里穿过；第 10 步按它判断哪些地块是规划式的长条地块。
- **沿等值线修路是一个共用工具**：墙根巷是“离墙 5 m”的等值线，平行街是“离引导线 70 m、140 m”的等值线，横街是“沿引导线 100 m、200 m……”的等值线，都用同一个工具（§11.3）。

### 11.3 节点

**`RoadKind`** 改为 `Main, Outer, Street, Lane, Track`（按重要性排，同一段连线上小的赢）。`FrontageParcels` 按枚举顺序切地块，`RoadSearch` 在已有道路上的折扣按 `kind >= Street` 判断，巷和便道都自动排在街巷之后，不用改。

**9a `StreetRanks` 街巷分级**（路网分组，`ExtractRoads` 之前；只编辑 `road.links`）：在格子连线上反复剪掉“只连着一条路、又不是锚点”的格，被剪掉的街巷连线改为巷。主街、城外道路、便道不改，但算在每格的连线数里。结果：只通向一片地的尽头路和它的分叉是巷，连成环或连接两条路的是次街。节点参数只有“有无”。

`ExtractRoads` 加巷宽 3 m，街巷宽默认 4 → 5 m（参数名改为“次街宽”）。`RoadZoning` 的地标留空 `PlotClearance` 按次街半宽算：2.5 + 1.6 = 4.1 m。

**新工具 `tools/IsoStreets.cs` 沿等值线修路**：输入每格一个值（距离场）、目标值、可走的格。

1. 取 |值 − 目标| 不超过 0.75 格的可走格，按 8 邻域分成几片。
2. 每片取相距最远的两端（两遍广度优先），用 `RoadSearch.Find` 在这一片里连起来（比按格逐个连更直，也保证连通）。短于最短长度的片丢掉。
3. 每条路的两端，在一个距离以内有别的路时用 `RoadSearch.FindNearest` 接上去，没有就留作尽头。

**9b `WallLane` 墙根巷**（`SkeletonLinks` 之后；读 `road.zones`、`town.wall`、`town.gates`，编辑 `road.links`）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 有无 | 1 | |
| 离墙 m | 5 | 巷中线离墙线的距离（墙身约 2.6 m 厚，巷宽 3 m，巷外沿在 6.5 m） |
| 最短 m | 40 | 比它短的段不修 |

距离场是离墙线的距离（只算城内的格）；城门 8 m 以内的格从可走格里去掉，所以等值线在城门处断开，每段是两座城门之间的一段墙，两端在 12 m 以内接到主街上。地标用地（城堡、修道院贴着墙）、陡坡、水已经不在通行区里，等值线在那里断开，两端接最近的路。修出的都是巷。

`StreetBlocks` 的城墙内侧退让默认 8 → 7 m（墙根巷外沿 6.5 m 加一点余量）。`WalledInfill` 的离墙 8 m 不变：墙根这条带本来就不建房，现在铺了巷。

**9c `PlannedStreets` 规划街巷**（`StreetMesh` 之前；读 `road.zones`、`town.growth`、`region.routes`，编辑 `road.links`，写 `road.plan`）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 规划期 | 3 | 从第几期起按规划式（3：三期和四期；5：都不规划，等于关掉） |
| 街距 m | 70 | 平行街之间、平行街与引导线之间的距离：两排背靠背的地块，各约 33 m 深 |
| 横街间距 m | 100 | 沿引导线每隔多远一条横街 |
| 最小片 ha | 0.4 | 比它小的规划期成片地留给有机街巷 |
| 最短 m | 40 | 比它短的平行街或横街不修 |

1. **规划区**：规划期的建成格（城内三期，城外四期，城内的四期也算）中，通行区允许、离墙不在墙根巷带里的格，按 8 邻域分片，丢掉小片。
2. **引导线**：对每一片，取它 120 m 以内格数最多的那条过境道路（`region.routes` 的拉直折线）。离所有过境道路都超过 120 m 的片（目前没有），用它自己的主轴（主成分方向）上过形心的直线。
3. **沿引导线的坐标**：对片里和片周围 120 m 以内的格，算离引导线的距离 d（带正负号，分两侧）和投影到引导线上的里程 t。
4. **平行街**：在 d = ±70、±140 m……处用 `IsoStreets` 修路，可走的格限于本片。两端 1.5 倍街距以内有路时接上。
5. **横街**：在 t = 横街间距的整数倍处（错开已有的街巷：20 m 以内已有路格就跳过）用 `IsoStreets` 修路，可走的格是本片加上引导线一侧的一、二期建成格，从离引导线最远的平行街一直修到引导线（接上主街或城外道路）。
6. 修出的都记为街巷（之后 `StreetRanks` 再分级）。`road.plan` 记下每一片的格、引导线、平行街和横街的格子路径与目标偏移。

`StreetMesh` 和 `SuburbLanes` 改读 `road.plan`：撒点不落在规划区，新修的路只经过规划区以外的格或已有的道路格。三期后来又在城内楔形地的边角留下的零碎地仍由它们补。

为什么街距取 70 m：三期的格离主街 45–150 m，第一条平行街在 70 m，服务 35–105 m，正好接上主街两侧一、二期约 45 m 深的带；第二条在 140 m，服务 105–175 m。三期地块现在平均深 31–36 m，背靠背两排加一条街约 70 m。四期离城外道路 45–70 m 的格占三到四成，第一条平行街就在它们中间。

**9d `Squares` 小广场**（`LandmarkAccess` 之后、`StreetRanks` 之前；读 `road.zones`、`town.wall`、`town.gates`、`town.landmarks`，编辑 `road.links`，写 `road.squares`）：

| 广场 | 形状 | 规则 |
| --- | --- | --- |
| 门内广场 | 梯形：门口宽同主街，往里 25 m 处宽 20 m | 沿城门的向内方向，裁到城内、离墙 2.5 m 以外、可建设格、不压地标用地；面积小于 200 m² 时放弃并提示 |
| 教堂前庭 | 长方形：宽同教堂用地，深 12 m | 贴在教堂用地的西端（祭坛朝东，门在西）；离路超过一格时，从前庭中间修一段街巷接到最近的路 |
| 城堡门前 | 长方形：宽 20 m，深 15 m | 贴在城堡用地朝向市场的一边中间（地标通路就从这一边出去） |

城门外不另加车马场：墙外 15 m 的退让带本来就空着。路口放宽不做。

`SquareSet` 是广场列表（多边形、类型、所属城门或地标的编号）。`ExtractRoads` 读 `road.squares`，把广场并进 `roads` 的铺装区，`StreetBlocks` 照常扣掉。

### 11.8 风险

- **楔形地的形状**：三期是长臂之间不规则的楔形，平行于一条过境道路的街到了楔形的另一边会斜着碰上另一条臂，留下三角形的街区。这在历史城镇里也常见（新区和老城交界处），只要三角形不太尖；太尖的（夹角小于 30°）由最短长度和 `FrontageParcels` 的最小面积自然去掉。
- **陡坡切断平行街**：平行街只走通行区（坡度 12° 以内），坡地上会断成几段。断开的两段各自接最近的路，不硬连。
- **规划区和有机区接缝**：横街从规划区穿过一、二期的带接到主街，可能和 `StreetMesh` 后来修的街巷几乎重合。`StreetMesh` 撒点时离已有道路格至少半个间距，平行重合的情况应该很少；出现时在截图上看，必要时让 `StreetMesh` 的连线也不能在离横街一格以内平行走。
- **墙根巷被城堡、修道院截断**：修道院离墙只有 7–24 m，城堡贴墙，墙根巷在这些地方变成尽头，被分级为巷（它本来就是巷）。不处理。
- **次街加宽减少房屋**：街巷 4 → 5 m 会让临街地块浅 0.5 m，城内大约少几栋房子；巷收窄补回一些。结果写进 9a。
- **街巷网的随机变化**：房屋数在同一种子上会随街巷网的随机种子差 ±25 栋左右（8b），9a–9d 的结果按“规则带来的变化”和“随机变化”分开说明。

## 12. 第 10 步详细设计：地块与后院

### 12.1 现状

在三个种子（73129 / 7 / 22017）上量了第 9 步之后的地块、房屋和水源。地块分组的依据是探针所在的格。

| 组 | 地块 | 面宽中位数 m | 进深中位数 m（九成分位） | 房屋占地块 | 房后到地块尾端平均 m |
| --- | --- | --- | --- | --- | --- |
| 城内老城（有机） | 228 / 186 / 172 | 7.8 / 8.2 / 8.6 | 20.5 / 20.1 / 21.5（34–41） | 38–43% | 12–14 |
| 城内规划区 | 66 / 108 / 137 | 8.0–8.8 | 21.7–23.9（33–45） | 34–37% | 14–16 |
| 城外有机 | 72 / 80 / 70 | 12.8–13.3 | 20.5–22.5（35–48） | 27–29% | 15–17 |
| 城外规划区 | 50 / 63 / 68 | 12.6–14.1 | 20.2–24.5（38–46） | 27–28% | 16–18 |
| 作坊 | 61 / 46 / 45 | 24–25.5 | 18.5–24.5 | 18–26% | 11–18 |

- **地块铺满了街区**：街区的 91% / 93% / 94% 已切成地块。
- **街角**：不算作坊，有 137 / 157 / 159 块地块（约三分之一）在临街线以外还有一条边贴着方向不同（夹角超过 35°）的路。另有 49 / 30 / 43 块地块的后面也是路。现在这些地块的房子和别的地块一样，只朝前面那条街。
- **规划区不需要另切**：规划区的地块只有 15–25% 深 28–36 m（两条平行街之间背靠背的理想深度），37–43% 浅于 20 m。浅的多在横街和街角旁，是街区形状造成的，不是切法的问题。规划区也没有后巷（9c 改成了平行街），所以原方案里“规划区直接切到后巷”这一条取消。
- **后院有地**：房子后面平均还有 12–18 m 深的地，城内的地块只有四成左右被房子盖住。
- **院墙的长度**：地块的边不贴路的部分合计 22 / 26 / 26 km。两块地块共用的边算一次，约 11 / 13 / 13 km。
- **城门附近的地块**：每座城门 60 m 内临主街或城外道路的地块有 3–15 块，面宽 5–18 m，没有一块够做带车马院的客栈（16 m 以上）。
- **离水远**：建成格离水 80 m 以内的只有 8% / 14% / 25%，超过 150 m 的 72% / 72% / 58%。
- **水井的候选位置**：路口（三条路以上相交）有 56 / 80 / 78 个，其中城内 32 / 43 / 51 个。

### 12.2 原则

- **不改切法，只加信息**：`FrontageParcels` 的切法不动（9b 刚调好），地块类型由一个新节点在切完之后判断。只有客栈大院要把相邻两三块地块并成一块。
- **院落是房子以外的东西**：院墙、后屋、菜园都放在一个新键 `yards` 里，由房屋之后的节点生成，不改 `buildings`。第 12 步建筑类型才决定后屋的造型和房子朝街角的方式。
- **水源只算井和河**：服务距离是常数（80 m，中世纪城镇的井大约每两三条街一口），不做水文。
- **画法先做到能检查**：院墙画成细线，后屋画成低矮的方块，菜园画成绿色的地面，水井画成石砌的井台。造型细节放到第 12、13 步和视觉阶段。

### 12.3 节点

**`Parcel`** 加两项：`Kind`（`ParcelKind { General, Strip, Corner, Court, Trade }`）和 `Side`（街角地块贴着侧街的那一段，两个端点；其余为空）。`FrontageParcels` 给出的都是 `General`（作坊用地是 `Trade`）。

**10a `ParcelKinds` 地块类型**（街区与地块分组，`FrontageParcels` 之后；读 `roads`、`town.gates`、`town.plaza`、`town.wall`，编辑 `parcels`）：

1. **作坊**：用途是湿作坊、火作坊、水磨的，类型是 `Trade`，不再改。
2. **街角**：沿地块的边每 1 m 取点。离一条路（非便道）的路面不到 1.2 m、这条路与临街线的夹角超过 35°、又不在临街线上（离临街线超过 2 m）的点，就是贴着侧街的点。这些点连成的一段长 4 m 以上时，地块是 `Corner`，`Side` 记这一段的两端。
3. **客栈大院**：每座城门往里、往外各 60 m 内，以及市场边上，各找一处。候选是临主街或城外道路、用途不是作坊的地块，和它在同一条路同一侧的相邻地块合起来（最多三块，地块要共用一条边，共边长度至少是较浅那块的七成）。合起来的面宽在 16–26 m、合并后仍是一个环的，取面宽最接近 20 m 的一组，并成一块 `Court`。门内门外各一处、市场边一处，每处只做一次。
4. **长条**：其余临主街、城外道路、次街的地块，进深至少是面宽的两倍的是 `Strip`。
5. **其余**是 `General`。

参数：大院找多远（默认 60 m）、大院面宽范围（16–26 m）、长条的进深面宽比（2）、街角最短的侧边（4 m）。

**10b `Yards` 院落**（建筑分组，`GableHouses` 之后；读 `parcels`、`buildings`、`roads`、`town.wall` → 写 `yards`）：

- **院墙和篱笆**：每块地块的边，去掉贴路的部分（离路面不到 1.2 m），剩下的是边界。两块地块共用的边只记一次，记成 `Fence(Points, Kind)`；城内是石墙（`Wall`，高 2 m），城外是篱笆（`Hedge`）。
- **后屋**：房子后面到地块尾端还有 10 m 以上、地块面宽不小于 5 m 时，在地块尾端放一间后屋，宽为面宽减 1 m 和 8 m 中较小的一个，深 4–6 m（随机），贴着地块的后边，离两侧各 0.5 m。后面是路的地块，后屋就朝那条路开门（第 12 步用）。用途决定种类：市场核心是仓房，居住是作坊间，城外街区是畜棚，作坊是料棚。放不进地块（凹进去的边）时依次收窄、收浅，还不行就不放。
- **菜园**：地块减去房子、后屋（各向外扩 1 m）后剩下的、面积 30 m² 以上、最窄处 3 m 以上的部分，记成 `Garden(Region)`。菜畦的条纹是地面纹理，留到视觉阶段。

参数：后屋需要的最小后院深度（10 m）、后屋深度范围（4–6 m）、种子。

**10c `Wells` 水井**（街区与地块分组，`ParcelKinds` 之后；读 `roads`、`town.plaza`、`road.squares`、`town.growth`、`site.shore` → 写 `fixtures`）：

1. 候选位置：市场中心、每个门内广场的中心、每个路口（三条路以上相交的节点），再加上主街、次街、巷、城外道路上每 40 m 一个点（给离路口远的长臂兜底）。都在铺装区里。
2. 每个建成格离水 80 m 以内的算已有水源。
3. 先放市场的井，然后反复挑一个能服务最多“还没有水源的建成格”（80 m 以内）的候选点，候选点离已有的井至少 40 m，直到所有建成格都有水源，或者再也加不出新的。
4. `FixtureSet` 是 `Fixture(Kind, Position)` 的列表，`FixtureKind { Well, MarketCross }`（市场十字留到 13b）。

服务距离 `Wells.Reach = 80` 是常数（契约要用），不做参数。

### 12.7 风险

- **街角判断的误报**：弯街上的地块，临街线和同一条街的弯处也会有 35° 以上的夹角。侧边的点要贴着另一条路（不是临街的那条），长度要 4 m 以上；10a 时在截图上看街角的轮廓是否都在路口。
- **合并后的大院形状怪**：相邻地块的后部可能一深一浅，并起来是 L 形。限定共边长度至少七成，并且合并后仍是一个环；不满足就换下一组，都不满足就不做，写进结果。
- **院墙的网格量**：三个种子各有十几公里院墙，画成带厚度的墙体会有几万个面。10b 先画细线，墙体放到第 12 步，按材质合并。
- **后屋挤占菜园**：后屋放在地块尾端，菜园只剩房子和后屋之间的一条。城外的地块深 20 m 左右、房子深 7–10 m，后院 10–17 m，放下 4–6 m 的后屋后菜园还有 4–10 m，可以接受。
- **井太多**：路口和道路采样点多，贪心选点会在边角为几格地加一口井。如果井多到二十口以上，再考虑给“每口至少新服务多少格”加一个门槛（契约的 80 m 要随之放宽），写进结果。

### 13.2 原则

- **规划读原地形，造型读整平后的地形**（§3）。采样、评价、选址、生长、街巷、地块都不变，指纹里这些部分不动；整平只改变“东西画在多高”和房屋的基座、檐口。
- **仍然只有一个高度来源**：整平后的高度也是一张与地形高度网格同分辨率（1 m）的网格，地面绘制原样导入它，城市叠加层在它上面双线性插值。不是“地面用网格、城市用解析形状”两套，否则路面和地面之间会有几厘米到几十厘米的缝。
- **形状是数据，网格是它的烘焙结果**：`GradePlan` 同时带着形状（道路走廊、平台、挡土墙，供显示和契约检查）和烘焙出的高度补丁（供取高度）。节点决定形状，烘焙是共用工具。
- **挖填有上限，上限让步的地方要标出来**：坡度上限和挖填上限冲突时保挖填上限，那一段记为“陡坡段”（巷可以画成台阶），而不是为了一个坡度数字挖出四米深的路堑。
- **只动城镇和道路周围**：离任何铺装、地块、地标一定距离以外，叠加量恰好为 0；水面格不动（桥是架在上面的，不是填出来的）；离图边 20 m 以内叠加量淡出到 0，裙边不用重建。
- **每个新元素都可以关掉**（§3）：三个节点各有强度或“有无”参数，全部关掉时 `grading` 的叠加量全为 0，画面和指纹与现在逐位相同。这也是 11.0 的验收条件。

### 13.3 数据：`grading`

`GradePlan`（`city/data/Grading.cs`）：

| 成员 | 内容 |
| --- | --- |
| `Corridors` | 道路走廊：路段编号、中线折线、每个顶点的目标高度、路宽、是否陡坡段 |
| `Platforms` | 平台：多边形、平面（一个高度，或市场那样带坡的平面：基准点、坡向、坡度）、类型（市场、小广场、地标、地块临街、桥头引道） |
| `Walls` | 挡土墙：折线、上下高度 |
| `Patch` | 烘焙结果：以原点对齐的 1 m 网格上一块矩形范围内的叠加量（整平后高度 − 原地形高度），范围外为 0 |
| `HeightAt(p)` | 原地形高度 + `Patch` 的双线性插值 |

烘焙（`tools/GradeBake.cs`）：按优先级把形状栅格化进补丁——桥头引道 > 道路走廊 > 市场和小广场 > 地标平台 > 地块平台；形状边缘以外按放坡带混合回原地形（道路两侧 1:1.5，平台按它自己的放坡或挡土墙）。只在各形状的包围盒里逐点算，不扫全图。每个编辑 `grading` 的节点复制形状列表、加上自己的、重新烘焙受影响的范围。

`ITerrain` 不变。`Main` 用 `GradedTerrain`（实现 `ITerrain`，`HeightAt` 转给 `GradePlan.HeightAt`，其余转给原地形）作为渲染、相机、探针的地形；`grading` 还没生成或正在重算时就是原地形。

### 13.4 节点

新分组“地形修整”，在“街区与地块”之后、“建筑”之前。节点顺序是 桥 → 道路纵断面 → 平台（与 §4.3 写的顺序不同：桥面高度是道路纵断面的约束，要先定）；实施顺序仍是先道路、再平台、最后桥（§13.7），桥做出来之前渡口两端按现状处理。

**`Bridges` 桥**（11c）→ 写 `bridges`

- 读 `region.crossings`、`region.routes`、`roads`、`site.shore`、`site.above_water`。
- 每处使用中的渡口：桥面高度 = 水位 + 净空（默认 2.5 m）与两岸桥台处地面的较大者；桥台不放在 `BankA/B`（在水下），而是沿道路向两岸外走到地面高出水位 1 m 以上的第一点；桥墩按跨度等分，间距不超过 12 m，落在水面格上；桥面宽取所在道路的路宽。
- 写出桥面折线和高度、桥台、桥墩。两岸的引道不由它整平，而是作为下一节点的固定高度约束（引道自然就是纵断面里的一段填方）。
- 参数：净空、最大墩距、“有无”（关掉时没有桥，纵断面在渡口两端取岸上高度直线相连，等于现在的桥面板）。

**`RoadProfiles` 道路纵断面**（11a）→ 写 `grading`

- 读 `roads`、`road.squares`、`town.plaza`、`bridges`、`site.shore`。
- 第一步，铺装面：市场拟合一个平面，坡度不超过上限（默认 3%，排水和落差都靠它）；小广场各取一个水平面，高度取它接的那条路在入口处的高度。
- 第二步，路口高度：每个路网节点取原地形高度为初值，市场里的节点取市场平面上的高度，桥台节点取桥面高度（这两类固定）；然后在路网上迭代，把每条路段两端的高差压到“坡度上限 × 路段长”以内，同时每个节点离原地形不超过挖填上限。两者冲突时保挖填上限，路段记为陡坡段。
- 第三步，路段纵断面：两端固定，中线每 2 m 一个点，取原地形高度后平滑（去掉 20 m 以内的起伏），再做坡度限幅；陡坡段只平滑、不限幅。
- 第四步，横断面取平：走廊宽度内同一里程处高度相同；两侧 1:1.5 放坡，贴着地块的一侧交给平台处理。
- 坡度上限（参数，默认值待 11a 实测后定）：主街 8%、次街 10%、巷 15%、城外道路 10%、便道 15%；挖填上限 1.5 m。按 §13.1 的数字，§4.3 写的 6 / 8 / 12% 在主街上有两成长度做不到。
- 摘要：各级道路的最大坡度、陡坡段长度、最大挖深和填高、土方量。

**`Platforms` 平台**（11b）→ 编辑 `grading`

- 读 `parcels`、`town.landmarks`、`town.wall`、`roads`，以及上一节点的 `grading`。
- 地块：每块地从临街线起一个进深（默认 14 m，覆盖房子和它前面的门口）整成一个水平平台，高度 = 整平后街道在临街线中点的高度，但离该范围原地形的平均高度不超过 1 m（超过时取到限值，差出的部分是门口的台阶或半层基座）。相邻两块平台高差超过 0.3 m 记一道挡土墙；平台后沿到后院按 1:2 放坡回原地形，高差超过 1 m 记挡土墙。后院不动。
- 地标：教堂、修道院、市政厅、麻风院各整成一块水平平台，高度取用地原地形的中位数；城堡取用地的 75% 分位高度（留在高处），四周本来就是城堡的墙，不另记挡土墙；刑场不动（它本来就是土丘）。
- 作坊：作坊地块同样按临街平台处理；湿作坊在易淹地上，平台不低于水位 + 1 m。
- 城防和田野（第 13、14 步）记下的壕沟、台地、引水渠到时由它读进来，这一步为空。
- 参数：平台进深、平台离原地形的上限、地标“有无”。
- 摘要：平台数、挡土墙总长、最大挖填。

### 13.6 契约

- `grading`：
  - 叠加量只在铺装区、地块、地标用地外扩一个范围（放坡带宽，默认 6 m）以内不为 0；水面格为 0；离图边 20 m 以内为 0。
  - 叠加量的绝对值不超过挖填上限加容差；桥头引道除外（它的上限是桥面高出原地形的高度）。
  - 每条道路走廊：相邻两个中线点的坡度不超过该等级的上限，陡坡段除外；陡坡段的总长不超过道路总长的一个比例（先定 15%，按 11a 实测调整）。
  - 走廊两端的高度等于所接路口的高度（路口处各条路同高，误差 5 cm）。
  - 走廊横断面：同一里程处路面两侧的整平后高差不超过 0.1 m。
  - 市场：是一个平面（各格离拟合平面不超过 0.1 m），坡度不超过上限；小广场、地标平台、地块平台是水平面。
  - 相邻平台高差超过阈值处有挡土墙；挡土墙都在某个平台的边上。
  - 全部关掉时叠加量全为 0。
- `bridges`：每处使用中的渡口一座桥；桥台在陆地上、高出水位；桥面不低于水位加净空；桥墩都在水面格上、间距不超过上限；桥面两端的高度等于道路走廊在该处的高度。
- `buildings`（加一条）：基座高度等于所在地块平台的高度；房屋四角处整平后的地面高差不超过 0.3 m（现在九成分位是 1.1–1.25 m）。
- 节点图：`grading` 过期只影响建筑分组；两次生成一致。

### 13.8 风险

- **Terrain3D 的局部导入**：`ImportImages` 接受位置参数，但只更新一块矩形时区块边界、LOD 和法线是否正确刷新没有试过。11.0 单独验证；不行就退回整张重导（2001×2001 的浮点图，拖滑条时会卡）。
- **漏改一处高度**：任何一个还读原地形的画法都会浮在空中或埋在地下。11.0 的“2 m 方台”截图就是为了一次看全；`CityView.Height` 必须是城市画法唯一的高度入口。
- **路口的高度互相牵制**：一个陡坡段会把相邻路口往它那边拉，迭代可能把整片街区抬高或压低。每个节点离原地形不超过挖填上限这一条兜底；迭代次数和收敛情况写进摘要。
- **平台之间的台阶太碎**：沿 8% 的街、8 m 面宽的地块，相邻平台差 0.6 m，一排房子就是一排台阶，挡土墙很多。可以让相邻几块地共用一个平台高度（按高差分组），11b 时看截图决定。
- **整平范围里的树和草**：城镇范围已经排除了植被；道路在城外的放坡带（两侧各几米）现在只排除了路宽加 3 m，要并进整平范围。
- **检视画面的场与地面错位**：采样场是按原地形算的，画在整平后的地面上，挖填处的“高程”“坡度”读数与看到的地面不一致。这是有意的（§13.2 第一条），在这两个场的说明里注明“原地形”。
- **耗时**：烘焙约 20 km 走廊加五百块平台；预算 0.3 s 以内，超过时把栅格化改成按行并行。

### 13.9 需要先定的取舍

1. **坡度上限与挖填上限谁让步**：本节按“挖填上限 1.5 m 优先，超出的路段记为陡坡段”写。另一种是坚持 §4.3 的 6 / 8 / 12%，接受个别路段三四米的路堑和挡土墙。
2. **`grading` 的表示**：本节按“形状 + 烘焙出的 1 m 高度补丁”写，保证地面和城市用同一份高度。§4.3 原来写的是“按需求值的形状”，不烘焙。
3. **市场是否允许带坡**：本节按“拟合平面，坡度不超过 3%”写；1300–2000 m² 的市场完全整平要在边上挖填 1 m 以上。
4. **节点顺序**：桥排在道路纵断面之前（§4.3 写的是之后）。

与 §13.3–13.7 不同的地方：

- **补丁范围是全图**：城外道路一直通到图边，所有形状的包围盒并起来就是整张图，补丁是 2001 × 2001 个值（没动的地方为 0），不是城镇周围的一小块。烘焙时只算形状周围的点；`GradedTerrain` 每次重新生成复制一份全图高度网格。耗时可以接受，以后要省内存再改成分块。
- **重新生成期间保留上一次的修整**（设计写的是退回原地形）：退回再抬起会让地面闪两次、多导入两次。
- **市场压在道路之上，小广场和平台在道路之下**（设计是道路压在所有平台之上）：贴着市场边走的路会把市场的边压斜，契约“市场是一个平面”查了出来。路在市场里的那一段本来就取市场平面的高度，所以市场优先不会产生台阶。
- **路段在进出市场和上下桥的地方切开**：`GradeCorridor` 是路段的一截，不是整条路段；每一截单独判断是不是陡坡段。
- **限幅后还要回头查挖填**：路口离原地形不超过挖填上限，并不能保证两个路口之间的中线也不超过；限幅后中线离原地形超过上限加 0.25 m 的那一截退回平滑后的原坡，记为陡坡段。
- **陡坡段的上限放到 25%**（设计先定的 15%）：种子 19 是 15.9%。
- **桥面是桥台到桥台的直线**：道路中线沿 4 m 格走，过河的那一段有小折，照着它画的桥面是锯齿形的。桥墩按桥面直线下的水面范围等分，不再取道路上的点。
- **桥没有“有无”参数**：关掉后道路会直接沉到河床上，没有意义；只有净空、最大跨度和桥台高出水位三个参数。
- **平台进深 16 m**（设计 14 m）：市场核心的房子最深 15 m。挡土墙的高差阈值统一为 0.5 m（设计是相邻平台 0.3 m、后沿 1 m）。
- **房屋的契约是“墙内 1.5 m 处”的地面高差**：房子的山墙贴着地块的边，那里的地面正好在两块平台之间的台阶上，量墙角会把邻居的平台算进来。阈值 0.5 m、允许一成的房子超过（比平台深的房子、退后的作坊棚屋会伸到后院上）；设计写的是全部不超过 0.3 m。
- **没有做的**：`street_steep.png` 机位；陡坡的巷画成台阶；`GroundCover` 的局部更新（现在整张高度贴图重传）；避让区没有并上城外道路的放坡带；相邻地块共用平台高度（§13.8 的“台阶太碎”，现在挡土墙有三四公里）。

试过但没有采用的：

- 路面在离两端 8 m 内放松（采用了，但几乎没有减少台阶，路口处的冲突本来就少）。
- 每个点只取离它最近的那段中线的高度：台阶形中线在内拐角处反而跳变，种子 11 从 7 处升到 20 处；改为先把中线切角平滑再取最近点后为 21 处，留下的都是上面说的之字形路。

留给规划层面的：过境道路的之字形（全图寻路的最小折返长度，或寻路后再拉直一次）；便道不要贴着已有道路平行走；市场平面坡度上限与接出去的道路坡度的关系。

## 14. 第 11 步重做：先台地、后地块

> 状态：完成（2026-11-12，分支 `terraces`）；结果和与本节不同的地方见 §14.12（14.0–14b）、§14.13（14c）。§14.9 的四个取舍按本节写的默认做法定下；按提交 de9edb6 的代码核对过，核对后改动的地方见 §14.11。§13 的结果（§13.10、§13.11）是这一节的出发点：桥、道路纵断面、全局求解的烘焙和 `GradedTerrain` 都保留，重做的是“平台”和它在节点图里的位置。§13.11 末尾留给规划层面的三类冲突（之字形过境道路、贴着主路的便道、市场平面与陡路）不在这一节里。

### 14.1 现状

§13.11 之后：挡土墙 4054 / 4709 / 3613 m（种子 1–20 为 2.8–6.3 km）。§13.11 量的修整后地面上相邻两点高差超过 0.6 m 的台阶（73129 / 7），最多的一类是“地块平台｜地块平台” 826 / 1258 处，其次“地块平台｜道路” 150 / 173（这两类是逐个烘焙时量的，两侧都是钉住的形状，全局求解不改变它们），“地块平台｜过渡带”求解后 193 / 178。房屋的契约只能放到“墙内 1.5 m 处四角高差 0.5 m、允许一成超过”。截图上沿坡街的地块一块一级，有的地方高低交错。全局求解消掉了过渡带里的假台阶，剩下的碎台阶来自平台本身，原因在数据和顺序上，不在参数上：

- **整平的单位是地块。** `Platforms` 给每块地单独定一个高度：街道在临街中点的高度，夹到这块地原平均高度 ±1 m 以内。相邻两块各自夹、互不相看，所以台阶是每 7–12 m 一级，而且在原地形有小起伏的地方忽上忽下。§13.8 说的“相邻地块共用平台高度”没有做，也做不好：地块已经切完，平台只能跟着地块的边走。
- **台阶的位置由地块决定，不由地形决定。** 平台裁在地块的轮廓里，街区与铺装、地标用地本来互不重叠（`StreetBlocks` 扣掉了它们），所以平台之间并没有抢同一处地面；台阶全在地块的分界上。地块分界是按随机面宽切的，台阶也就落在随机的位置，一条坡街上有几块地就有几级。高度场是 1 m 格点的双线性插值，任何台阶两侧各有最多 1 m 的插值斜面，房子的山墙贴着地界，墙角正落在斜面上（这就是房屋契约要量“墙内 1.5 m”的原因）。
- **挡土墙与画出来的地面不一致。** `Platforms.Walls` 按“道路修整后、平台烘焙前”的地面（`roads.HeightAt`）比高差：平台后沿外是原地形，于是记一道墙；但全局求解时后院是自由地面，会从平台边放坡回原地形（最远 `GradeBake.Reach` = 10 m），画出来的墙低的一侧被坡埋住。
- **单向决定。** 路先定高，平台只能迁就路；地块先切好，平台只能迁就地块。没有一步同时看到一个街区里的所有临街面。

动手前（14.0）在三个种子上补量这几项（共七项），作为验收的基准：

| 量什么 | 怎么量 |
| --- | --- |
| 沿街相邻平台的高差 | 同一条路段同一侧、前后相邻的两块地块平台，高差的中位数、九成分位、最大值；按道路等级分 |
| 反向台阶 | 沿街下坡方向上，后一块平台比前一块高出 0.1 m 以上的比例 |
| 挡土墙 | 段数、平均段长；按位置分：地块之间、地块与后院、地块与街、地标周围 |
| 重叠点 | 烘焙时落在两个以上形状里的 1 m 格点数（按道路之间、道路与小广场、平台与其他分开），和这些点上各形状高度的最大差；预计只有前两类 |
| 墙与地面 | 每道挡土墙低的一侧，烘焙后地面离墙外 1 m 处比 `Low` 高出多少（§14.1 第三条） |
| 跨台阶的房屋 | 房屋墙内 1 m 处四角高差超过 0.1 / 0.5 m 的栋数 |
| 临街高差 | 平台高度与街道在临街中点高度之差（被“离原地形 ±1 m”夹住的那部分）的分布 |

### 14.2 方案选择

比较过两种重排：

1. **粗规划 → 全局整平 → 细规划**：规划到街区为止仍读原地形；然后一次把整个城镇分成台地、定高、记挡土墙；地块、房屋在台地之上切和放。
2. **先台地化，再规划**：在原地形上先做台地，所有规划节点读台地化后的地形。

取第一种。第二种的问题：台地的尺度应该由街距和地块进深决定，在不知道城在哪、街朝哪时做台地只能猜，地块还是会跨在台地边上；台地化后的坡度场只剩 0° 和近 90°，`BuildableLand`、`Habitability`、`TravelCost`、`LandformPosition`、渡口和过境道路寻路的阈值与契约都要重标定；按历史分期生长的城镇长在事先整好的地上，因果倒置；台地化排在最上游，改它的任何参数整张图都要重跑。“先台地”只适合城外的农业台地（葡萄园），那是第 14 步里排在用地分区之后的一个节点，不是整条管线的第一步。

第一种的分界线要划在**街区之后**，不能只到用途分区：整平要铺路面，就要知道路在哪；坡街本身就是连接各级台地的坡道，纵断面要和台地一起定。

### 14.3 原则

- **规划读原地形，细分读台地**：采样到 `StreetBlocks`（含地标用地、市场、小广场、路网）不变，指纹里这些部分不动。地块和建筑读 `terraces` 这份结构数据（哪块台地、边在哪、多高），不在整平后的高度场上重算坡度或可建设判定。
- **一处地面一个主人**：城镇用地分成互不重叠的几类：铺装（道路走廊、市场、小广场）、地标台地、街区台地、自由地面（后院、墙根空地、城内园地、放坡带）。前三类各有确定的高度，自由地面才由烘焙求平滑。现在的平台已经互不重叠（街区扣掉了铺装和地标），这一条写成契约固定下来；道路之间在路口的重叠、小广场与穿过它的走廊照旧在烘焙里取平均。
- **台地的单位是“街区沿街的一段”**，不是地块：一段包含几块地的面宽，地块在台地里切，地界落在台地的边上，挡土墙就是地界或后墙。
- **台阶是真实的，不消灭它，让它有序**：沿街单调（顺着街的坡一级级下去，不忽上忽下）；每级高差有上限；同一街区里台地尽量少。沿 8% 的街每 12–15 m 一级、每级约 1 m 是对的。
- **台地和地块用同一个先后次序**（先主街、再城外道路、街巷、便道；长的在前），街角归哪条街，台地和地块一致。
- **仍然只有一个高度来源**（§13.2）：台地也烘焙进 `grading` 的补丁，地面、道路、房屋、相机都读它。
- **可以关掉**：台地关掉时 `terraces` 为空，地块按现在的方式切，房屋地坪取四角处整平后地面的最高点，等于只修道路。

### 14.4 数据：`terraces`

### 14.5 节点

分组和顺序（`StreetBlocks` 移到“路网”末尾，“街区与地块”改名“地块”并排到“地形修整”之后）：

```
路网：…… StreetRanks → ExtractRoads → StreetBlocks
地形修整：Bridges → RoadProfiles → Terraces → Platforms
地块：FrontageParcels → ParcelKinds → Wells
建筑：GableHouses → Yards
```

`Bridges`、`RoadProfiles` 不变（它们只读路网、广场、渡口，本来就不读地块）。`Wells` 不读地块，跟着分组移动，结果不变。

**`Terraces` 台地**（新）→ 写 `terraces`

- 读 `blocks`、`roads`、`grading`（道路纵断面的版本）、`town.landmarks`、`land.use`、`town.wall`、`site.shore`（用途和城内外决定作坊台地进深，与地块取用途的方法 `LandUses.PlotUse` 相同）。
- **临街段**：与 `FrontageParcels` 同一种走法：按“先主街、再城外道路、街巷、便道，长的在前”逐条道路段、两侧各走一遍，沿中线向外偏半个路宽，找它前面的街区；临街线取在街区真正开始的地方（墙根巷边的街区离路面 1–4 m；市场边的街区临的是市场，离穿过市场的那条路的中线更远）。同一道路段同一侧、跨过折线拐点连续临着同一个街区的部分是一条临街段。临街段上每 1 m 一个站点，门前高度取修整后的地面在临街线外 1.5 m 处的高度（`grading.HeightAt`，与现在 `Platforms` 取街道高度的位置相同），所以临市场、小广场的地块自然取市场平面和广场的高度。
- **沿街分段**：每条临街段用动态规划选断点。一段的高度 = 街道在段中点的高度，夹到这段 `Level` 原地形平均高度 ±`MaxOffset` 以内；代价 = 段内各站点“台地高度 − 街道高度”的平方和 + 每段一个固定代价；约束：段长不小于最短台地长（临街段本身更短时整条一段），段内各站点的门前高差不超过 `Doorstep`。街比“台阶高差上限 ÷ 最短台地长”还陡、约束满足不了时，按最短台地长切，记为陡街台阶。
- **保序**：每条临街段在街道单调的区间内，对各段高度做保序回归（相邻违序的段合并取平均），夹到原地形之后也不出现反向台阶。
- **向后延伸**：所有段按“先主街、再城外道路、街巷、便道，长的在前”的次序，一齐从临街线向街区里每轮 2 m 延伸（和 `FrontageParcels` 的 `GrowBack` 同一个做法，抽成 `tools/FrontSweep`），相遇或到最大进深（同地块的 50 m）停下，得到每段的 `Reach`；`Level` = `Reach` 中离临街线不超过台地进深的部分。街角处先到的那条街占住，与地块一致。
- **合并**：同一街区里共边的两块台地，高差小于 `MergeStep`、合并后两边的门前高差仍在 `Doorstep` 以内的，合成一块（高度取按临街长度的加权平均）。从高差最小的一对开始，直到合不了。面积小于 60 m² 的碎块并给共边最长的邻块。
- **地标台地**：教堂、市政厅、修道院、麻风院各一块，取用地原地形的中位高度；城堡取 75% 分位；刑场不整。规则与现在 `Platforms` 的相同，搬到这里，因为相邻街区台地的墙要看它。
- 参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 有无 | 开 | 关掉时 `terraces` 为空 |
| 台阶高差上限 m | 1.0 | 沿街相邻两块台地的高差上限；与最短台地长一起决定坡街上多长一级 |
| 最短台地长 m | 14 | 一块台地的临街长度下限（约两块居住地块）；街比“上限 ÷ 它”（约 7%）陡时台阶超过上限，记为陡街台阶 |
| 门前高差 m | 0.5 | 台地高度与它门前街道高度之差的上限 |
| 离原地形 m | 1.0 | 台地高度离它 `Level` 原地形平均高度的上限（同现在的“平台离原地形”） |
| 台地进深 m | 16 | 整平的深度；作坊用途的段另用作坊台地进深（默认 28 m，棚屋可以退后 12 m） |
| 合并高差 m | 0.25 | 共边台地高差小于它时合成一块 |
| 地标台地 | 开 | 关掉时地标用地贴着原地形 |

- 摘要：台地块数（街区、地标），平均临街长度，沿街台阶处数、平均和最大高差，陡街台阶处数，合并次数。

**`Platforms` 平台**（重写）→ 编辑 `grading`

- 读 `terraces`、`site.shore`，以及 `RoadProfiles` 写的 `grading`。
- 每块台地的 `Level` 成为一个水平平台。湿作坊所在的台地不低于水位 + 1 m（这条高度规则在 `Terraces` 里定，这里只写入）。

### 14.7 契约

### 14.9 取舍（已定，2026-11-12）

四条都按本节写的做法定：后院不整、台阶高差取连续值、`StreetBlocks` 进“路网”、街角允许合并。另一种做法留在下面，14c 看截图时如有需要再改。

1. **后院整不整**：本节按“只整临街进深，后院是自由地面”写，地块之间沿进深方向只有一道墙（台地后沿）。另一种是后院也按原地形分成第二级台地，墙更多但后院是平的。定为不整，14c 看截图。
2. **台阶高差取连续值还是固定级差**：本节按“段中点的街道高度，夹到原地形和门前高差以内”取连续值。另一种是取 0.5 m 的整数倍（台阶按级数画），全城的台阶看起来更统一，但门前高差最多多出 0.25 m。
3. **`StreetBlocks` 归哪一组**：本节放进“路网”末尾（街区是路网围出来的）。另一种是放在“地形修整”开头，“路网”保持只有路。只影响界面上的阶段划分。
4. **街角两条临街段的台地能不能合并**：本节允许（合并规则不看临街段）。不允许的话，街角那一块总是单独一级。

### 14.10 风险

- **路仍然先定高**：路在挖填上限（1.5 m）以内偏离原地形时，两边的台地被“离原地形 1 m”夹住，门前高差可能超过 `Doorstep`。14.0 先量“临街高差”的分布；多的话，下一步让 `RoadProfiles` 的路口迭代也参考两侧街区的平均高度（路与台地的双向调整），这一节不做。
- **街区形状不规则**：弯街、街角和墙根巷边的街区，向后延伸会留下细条和碎块。碎块并给邻块；细条不够一块地的，和现在地块的补空隙一样处理。
- **地块的面宽分布会变**：断点由台地定，地块循环在每小段末尾放宽或并块，面宽会更集中在上下限两端。14b 量面宽分布，偏得多就在 `Terraces` 的断点代价里加一项“段长接近面宽的整数倍”。
- **失效范围变大**：调道路纵断面的参数，地块和建筑都要重跑（现在只有平台和建筑）。地块约 0.3 s，可以接受。
- **以前的结果不再是现在的值**：地块、房屋、院落的数字都会变；结果按半步记，不改 §12、§13 的旧记录。
- **耗时**：`Terraces` 每个街区一次动态规划加一次向后延伸，预算 0.2 s；`Platforms` 的平台数从约 500 块降到台地数，求解的固定点更少，应不比现在（0.26–0.29 s）慢。

### 14.11 按代码核对后的改动（2026-11-12，提交 de9edb6）

- **现状的原因改写**（§14.1）：平台裁在地块轮廓里，与铺装、地标本来就不重叠，原稿说的“一处地面几个主人、靠权重调和”不成立；碎台阶的原因是台阶跟着随机的地块分界走。另找到一处不一致：挡土墙按烘焙前的地面比高差，后院求解时会放坡，墙低的一侧被埋住。现状补量加一项“墙与地面”。
- **`GradeBake` 不改**（原稿要删掉平台之间的平滑项和同类平均）：钉住的点权重 100–1000，对平滑项 1，台阶已经是陡的；平台之间没有重叠，同类平均对它们不起作用。剩下的斜面来自 1 m 格点的插值。
- **挡土墙改按烘焙后的地面记**（§14.5 `Platforms`）。
- **临街段改用地块的走法**（原稿是“街区边界离铺装 5 m 内、按最近道路段归组”）：地块是沿道路中线向外走出来的，临市场的地块挂在穿过市场的那条路上、离中线远；用同一种走法，台地的临街段和地块一一对得上。门前高度改取 `grading.HeightAt`，市场和小广场边自然取它们的平面。`Terraces` 多读 `land.use`、`town.wall`。
- **房屋契约在墙内 1 m 处量**（原稿 0.3 m 会量到台阶两侧的插值斜面）；地面连续契约不变（原稿要把 `WallGap` 收到 1 m）。
- **`MainInterface` 不改**：阶段和快捷键都按节点顺序生成；`Contracts` 有三处 `PlatformKind.Plot` 要改名。
- 核对过、与原稿一致的：`Bridges`、`RoadProfiles` 只读路网、广场、渡口；`Wells`、`Yards` 不读修整；现在没有“道路纵断面过期”的失效检查，§14.6 是新增；`FrontageParcels.GrowBack` 是依赖已占地块索引的局部函数，抽成 `tools/FrontSweep` 时要把“已占用”和“并入”一起带出去。

- **`sweep` 加一列“外露墙”**：房屋以外的挡土墙长度。挡土墙总长里有三成是房子的墙，这一列才是看得见的墙。
