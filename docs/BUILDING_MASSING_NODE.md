# 建筑体量生成节点

更新日期：2026-11-04。状态：首版已实现并接入地图界面，实际接口、运行与验证见文末。按当前区域布局和街区地块结果生成建筑占位、墙体与简化屋顶，继续一次生成、独立调参、显式重跑。下文保留设计依据和规则说明。

## 1. 本步要交付什么

**让完整城镇从二维土地分配变成具有街道界面、后院和公共建筑层级的三维体量。** 主要检查形态、占地、落地和空间通达关系。

首版包括：普通宅地的主屋体量与简单双坡屋顶、沿街组合、通院预留、基础落地，以及已有教堂和修道院院区中的简化建筑组合。保留城内、门外街带和城外机构聚落的差异。

主屋采用矩形或少量简单矩形组合。先完成能从多个角度检查的灰模；窗门装饰、木构细节、真实材质、室内、角色导航及正式美术资产后续消费同一份建筑数据。[道路平面几何定型](ROAD_GEOMETRY.md)已接入上游；道路美术资源与正式墙体继续另行处理。

## 2. 历史参考怎样影响规则

项目沿用约 1350–1450 年英格兰商贸城镇的工作假设。以下资料约束建筑组织，不直接提供统一模板或尺寸：

- [Historic England：Commerce and Exchange Buildings](https://historicengland.org.uk/images-books/publications/dlsg-commerce-exchange-buildings/heag121-commerce-and-exchange-lsg/) 记录临街商铺与上层或后部居住的组合，以及同一城市宅地中的附属作坊和仓储。由此保留商住、作坊住宅的组合语义，避免按单一用途把一整片城外区域做成工业区。
- [Barley Hall 的考古与修复记录](https://www.barleyhall.co.uk/about/the-archaeological-record/) 显示不同房屋部分有不同的年代和体量。可据此采用主屋与翼部等组合概念，但现代复原建筑的每处细节不作为默认历史事实。
- [Bayleaf 农舍，Weald & Downland Museum](https://www.wealddown.co.uk/buildings/bayleaf-farmstead-chiddingstone/) 为十五世纪大厅住宅提供个案。它属于英格兰东南部的地域类型，博物馆现有展示又以约 1540 年为背景；只作为城外住宅体量的对照，不将其直接套用到所有城市街屋。

建筑层数、屋顶角度、通道宽度等首版数值应标明为原型参数，并通过本项目的体量图校准。

## 3. 如何使用实际输入

首版声明 `environment: CityEnvironmentData` 与 `parcels: ParcelLayout` 两个输入。`ParcelLayout` 已引用同版道路、聚落与区域布局，院区和街道角色沿这些只读依赖读取，不再复制另一套城市状态。两个输入必须引用同一个采样快照。

拟定的业务入口如下，尚未加入代码：

```csharp
Task<BuildingSet> GenerateAsync(
    CityEnvironmentData environment,
    ParcelLayout parcels,
    BuildingOptions options,
    PcgContext context);
```

| 当前已有数据 | 本节点的使用方式 |
| --- | --- |
| `LandParcel.Shape` | 所有建筑占地、屋檐投影和地块内通行预留的归属边界，保留孔洞 |
| `Buildable` | 现有临街建筑带；首版普通主屋的占地必须完全位于其中 |
| `Frontage` | 选择主临街面、确定朝向和入口，保留实际道路边 ID |
| `Yard` | 明确保留的后院/园地，不按空白剩余空间随意加建筑 |
| `Uses` / `Use` | 决定商住、作坊住宅等功能组合与体量原型 |
| `DistrictId` / 区域片区角色 | 选取密度、沿街组合和高度的规则；不能只靠是否墙内决定全部建筑 |
| `InsideWalls` | 用于统计和预览，不能替代实际片区及街道规则 |
| `AllowsPartyWalls` | 允许检查共墙条件；该布尔值本身不提供共享墙边或邻居信息 |
| 道路中心线、占地与 `StreetRole` | 找到临街方向和道路边界，组织街段，检查入口连接与公共空间避让 |
| `Town.Precincts` | 单独生成教堂和修道院组合，不把这些院区伪装成普通住宅地块 |
| 环境高程与地块地形统计 | 前者用于具体支撑点采样，后者用于早期筛选；整块宅地高差不能直接当建筑地基高差 |

输入版本至少记录采样、聚落、道路和地块的结果修订号。地块节点修订号由宿主显式绑定；地图来源修订号不能代替节点结果版本。

## 4. 建筑规则按街段和片区组织

| 场景 | 首版体量方案 | 必须保留的空间 |
| --- | --- | --- |
| 核心中的主要商业街段 | 较连续的临街主屋，允许经检查的共墙；局部组合更高或更深 | 必要通院路径及已预留后院 |
| 普通核心街巷 | 小尺度街屋或独立主屋，沿真实街线落位 | 侧隙、通道与后院 |
| 城门外街带 | 连续街段和疏松段交替，主屋临街，后部园地明显 | 较深后院和局部间隙 |
| 修道院附近的普通宅地 | 依附局部道路的住宅/作坊住宅，整体较疏松 | 院区接入、宅地后院与片区间开放地 |
| 教堂院区 | 一座主建筑体量，塔楼为可选独立部分 | 院场、入口前空间和已有接入点 |
| 修道院院区 | 围绕预留院场布置少量长方形建筑翼部 | 明确的开放院场、入口和内部通行 |

这些是项目预设，不是对所有历史建筑的断言。城外街道也可以存在紧密商贸段，城内也允许低密度院落。规则优先级为：硬占地和通行条件 → 具体街段角色 → 宅地功能与片区 → 种子控制的小幅变化。

层高、屋脊方向、主要屋顶形式先在同一街段内保持一定联系，再按建筑实例小幅变化。避免每栋独立抽取完全不同的朝向、高度和颜色。

## 5. 一次生成的处理顺序

### 5.1 组织街段与通行预留

按道路边、道路侧和连续的临街范围组织相邻宅地。同一道路边上的两侧不能并成一排。弯曲道路按局部切线处理，不用整条道路的一个角度摆所有建筑。

通过实际共享边界识别邻接地块，先决定每个街段的建筑密度和必要通院位置。普通主屋靠近临街建筑带，不能默认放在宅地面积中心；面积中心也可能在凹形轮廓之外。

后院通行采用两种经几何检查的方式：地块内侧道，或有明确通行预留的共享小巷。共享通道需要保存涉及的地块、占地和连接关系，不能默认为允许穿过邻居后院。首版优先尝试少量相邻宅地共享通院通道；无法构成合法连接时退回各自侧道。

主屋、共享通道和后院出入口作为一组候选检查。宅地过窄、无法同时容纳最小主屋和通道时跳过并报告。不能在灰模上画一条穿过实体房子的线便声称后院可达。

### 5.2 放置普通主屋

对每个实际临街线段计算切向与朝内法向，朝内方向通过地块几何检查确定，不依赖端点顺序。按规则生成少量候选：调整沿街位置、面宽、进深，以及必要的侧道。

主屋优先使用一个完整矩形。若允许组合，使用少量简单体块，不直接把整块凹形 `Buildable` 拉伸成复杂建筑。对多片可建筑范围逐片试放，不横跨孔洞或分离区域。

必须检查完整占地对 `Buildable` 的包含关系，不能只检查中心和四角或包围盒。入口面朝向已绑定的临街道路，并在自有地块或明确通道内留出到临街边的连接。

每块地最多尝试有限数量候选，失败则保留空地与失败原因。首版不为放下一栋建筑修改道路、移动城墙或合并产权地块。

### 5.3 共墙与屋顶

只有实际共享侧边、方向相容、主屋轮廓可贴合且通行预留仍成立时，才生成共墙关系。允许共墙不等于强制填满地块全部面宽，也不允许两栋建筑占地重叠。

普通主屋首版用简单双坡屋顶，屋脊沿原型指定方向设置。组合翼部可用分开的简单屋顶。屋檐投影单独检查，默认不越出自有地块或侵入道路、院区和其他建筑；共墙一侧不生成互相穿插的挑檐。

相邻建筑可以有高度差。共享墙边界保存明确归属，预览和后续导出处理该界面，避免两个共面外墙或屋面片互相闪烁。

### 5.4 落地与高差

在实际建筑占地的角点、边缘分段及必要内部位置读取同版环境高度。地面层采用水平基准面，基础可形成到采样地面的裙边；基础暴露高度与入口高差都有明确上限。

先试图调整位置、缩小进深或更换合法候选。仍需过高基础、入口无法连接或支撑数据缺失时跳过，报告位置和原因。地块高程摘要只是筛选数据，不能直接将整块宅地的最高点作为每栋房子的地基高度。

首版基于采样地面做体量验收，当前默认 10 米采样不能证明每处真实地面都精确贴合。细分网格不增加环境信息；需要更精细落地时提高上游采样精度并重跑依赖链。本节点不原地修改地图。

### 5.5 院区建筑

教堂与修道院从各自的 `TownPrecinct.Shape` 取得允许用地和固定接入点，使用与普通宅地不同的组合规则。先为院场和入口通道划出明确区域，再放主建筑及可选体块。

首版教堂至少有一座主建筑体量；塔楼可按空间条件省略。修道院先用少量独立翼部表达组合，保留明显开放院场，不提前实现复杂的院落屋顶布尔系统。建筑必须位于院区内，不能占用周边普通宅地、道路或城墙缓冲带。

已存在且启用的院区主建筑按必需目标处理，失败时本次建筑结果不完成发布；可选塔楼等可以省略并报告。上游未启用公共院区时不强行添加地标。

### 5.6 整体检查与发布

检查全部普通主屋、院区建筑、屋檐、基础和通道之间的关系。合格的零面积共墙接触允许存在，非零面积的建筑穿插不允许。所有建筑引用、道路引用及相邻关系必须有效。

完成前检查版本和取消信号，成功后一次发布。普通地块部分失败可发布带诊断的结果；零普通建筑成功时明确报告布局不可用，不能仅靠两座公共建筑宣布普通宅地生成成功。

## 6. 当前地块契约需要怎样补充

`Buildable` 已表示主屋临街建筑带，`Yard` 已表示其余后院用地，首版普通主屋可以直接消费这两项。

街段组合、主临街面、主屋候选、入口与通院预留先在建筑节点内部形成工作计划，不要求先重写地块算法。需要经过邻居土地的通道必须在建筑结果中显式输出可追溯的通行预留；不能只留一个“可达”布尔值。

后院作坊、仓房等附属建筑后续需要明确的 `AccessoryBuildable` 范围。当前 `Yard` 不提供该许可，首版不会根据面积覆盖率自动占用后院。在此之前用功能标签表达作坊住宅，普通宅地主屋仍只在现有建筑带内生成。

## 7. 输出 `BuildingSet`

一个主要输出端口 `buildings`。下列按设计职责分组，实际代码以只读属性、集合和几何描述表达。

| 分组 | 内容 |
| --- | --- |
| `InputStamp` | 输入节点与结果修订号、参数快照、有效种子 |
| `Buildings` | 稳定建筑 ID、来源宅地或院区 ID、片区 ID、建筑角色与功能组合 |
| 占地与体量 | 完整平面占地、基础标高、墙高、楼层/大厅等体量标签 |
| 屋顶 | 屋顶类型、屋脊、檐高与屋脊高、水平投影、必要的分片关系 |
| `Access` | 门口、朝向、关联临街边/院区入口、自有侧道或共享通道范围 |
| `SharedWalls` | 相邻建筑 ID、共同边、墙面归属与屋檐处理关系 |
| `OpenSpaces` | 被保留的院场、后院及通行区域，不复制所有上游背景土地 |
| `Issues` | 跳过的宅地与原因、可选体块省略、输入精度和地面检查信息 |
| `Summary` | 城内外建筑数量、占地面积、沿街立面占用率、高度分布、成功/跳过数量 |

一个普通宅地首版至多有一栋主屋，一栋主屋可由少量体块组成；院区由多个独立建筑或体块组成，保留共同来源标识。结果是领域数据；Godot 显示网格由预览器构建，最终资产资源选择由后续场景布置消费。

## 8. 参数面板与可视化

常用参数提供建筑预设、主屋尺寸范围、墙高/层数范围、屋顶坡度、侧道宽度、允许的基础高差、变化程度和种子。使用按片区/街段的规则资源承载默认值，不将每种房屋形状做成图节点。共墙策略和公共院区开关可单独设置。

原型的起步配置如下，供实现和首轮观感比较使用，**均不是历史通用标准或建筑工程规范**：

| 配置 | 起步值或规则 |
| --- | --- |
| 普通主屋尺寸 | 面宽至少 3 米、占地至少 24 平方米；常用进深 6–12 米，并受实际建筑带限制 |
| 高度层级 | 核心主要街段偏向 2–3 层体量；其他住宅偏向 1–2 层，按原型允许大厅等不同层高组织 |
| 层高 / 屋顶坡度 | 普通层高 2.7–3.1 米；双坡顶起步范围 35–50° |
| 通院侧道 | 起步净宽 1.2 米，仍需完整几何通行预留，尚不构成角色导航验收 |
| 屋檐 | 目标外挑 0.25 米；边界或共墙约束不允许时减小到零 |
| 基础暴露高度 | 起步最大 1.5 米；超过时先换候选，不能直接大幅抬高整栋房屋 |
| 候选预算 | 每块地最多 12 组主屋候选，院区采用独立有限预算；全流程还设置总上限 |

常用面板先突出建筑预设、高度倍率、变化程度、通道宽度、地基高差和种子。具体面宽、进深、层高与屋顶范围放入原型资源的高级设置，避免首次打开就面对过长的参数表。

新增 **05 建筑体量**：输入状态、独立生成/取消、常用参数、结果摘要与定位。修改建筑参数只使建筑及其下游过期；改道路、地块或区域布局则传播失效。默认相机展示完整城镇，另提供主要街段、城外聚落和院区近景。

| 图层 | 内容与目的 |
| --- | --- |
| 体量总览 | 有深度测试和正常遮挡的墙体、简单屋顶、基础及城内外整体高低变化 |
| 功能与来源 | 用底色和选中详情区分住宅、商住、作坊住宅、院区；显示对应宅地 |
| 占地与通行 | 建筑边界、屋檐投影、保留后院、门口、侧道、共享通道及共墙边 |
| 地形与问题 | 基础高差、入口连接、跳过位置与具体原因；旧结果有明确标记 |

普通体量不能沿用目前平面调试层的整体抬高、半透明和关闭深度测试做法。诊断轮廓可另行叠加，正式体量使用自身正确标高与遮挡关系。

## 9. 交付与验收顺序

1. **普通主屋**：输入冻结、真实临街方向、矩形试放、基础落地、双坡屋顶及总览预览。
2. **街段关系**：建筑高度/形式的局部一致性、通院预留、可行共墙及屋檐检查。
3. **公共院区**：教堂、修道院体量与开放院场、入口连接。
4. **统一面板与完整验证**：四层预览、独立运行、取消、失效与固定种子复现。

至少用现有三组地图种子，外加斜临街面、凹形/多片建筑带、转角地块、狭窄宅地和较大局部高差等小样例验证。关键要求：

- 占地和屋檐不侵入其他建筑、道路、城墙、机构预留及未获许可后院。
- 已生成建筑的入口与临街边有正确对应，后院通行预留具有真实空间。
- 共墙有明确邻接关系，墙体与屋顶之间没有视觉穿插或重复面闪烁。
- 落地检查使用实际建筑范围；明显悬空、穿地或过高基础不能被默认成功掩盖。
- 机构建筑保持独立院区和开放院场，城外聚落不会被自动清空或吸收到城内。
- 轮廓数据、三角形、三维网格的投影与高度相符；检查逻辑区域，也检查实际渲染结果。
- 同输入和种子复现；局部调参复用上游；失败、取消和输入变化不发布部分结果。

形态验收使用完整城镇俯视图、至少两条街道的斜视近景、后院及公共院区近景。建筑总数不是首要指标，应优先检查沿街排列、主屋与院地的比例、重要建筑层级和城内外空间差异。

先依次生成环境采样、城镇区域布局、道路和街区地块，再选择 **05 建筑体量** 并独立生成。也可用以下命令：

### 规则与实际数据

- `BuildingGenerator.Generate` 接收同版环境与地块以及参数/取消上下文，`BuildingNode.RunAsync` 负责输入修订号与一次发布。调整建筑参数复用上游；任一上游过期或重跑，建筑随之过期。
- 主屋按实际临街切向与朝内法向试放，只接受完整位于建筑带的矩形。当前不生成后院附属房屋，后院用地保留。
- 共墙先尝试实际邻接的两块核心宅地，并为两家保存有明确归属的共享通院小巷；不满足条件则改为各自侧道。侧道/共享小巷必须到达各自实际 `Yard`，不能只停在主屋背后。
- 每块独立主屋最多 12 组候选，共墙组合另有有限试放；全次主屋试放上限 30,000。不能放置的地块写入原因和位置，仍保留上游土地。
- 屋顶按实际矩形的长短关系选屋脊方向，长院区翼部不跨其长边生成过高屋顶。屋檐不合法或侵入通道时收回到主屋轮廓。
- 基础基准由实际占地采样决定，限制暴露高差并生成至采样地面的墙裙。普通门前可用空间不足时拒绝高差入口；合格入口生成简化台阶。默认采样仍是近似地表。
- 教堂主殿用通高大厅标签，不能将其高度层级误读成三层室内楼板。塔楼可因占地、高差或接入条件省略。修道院生成开放一侧的少量翼部，院区通道通过有界可见通行网求解，避免斜穿建筑。
- 院区的外部接入带已补进 `TownPrecinct.Approach` 和 `Town.BuildingReserve`，地块生成会避让这段公共入口，防止普通宅地截断院区接入。
- 发布前检查全体建筑和屋檐的相交关系。共墙边有明确所有者，显示网格消除非所有者重复的共享墙面。

实际结果为 `BuildingSet`：只读建筑体量、屋檐投影、门口/通道、共墙、后院/院场、来源及问题。`BuildingMeshBuilder` 从同一数据生成有建筑 ID 和部件类型的三角形数据，用于渲染与投影验证；渲染网格不是节点的唯一事实来源。

### 验证与当前范围

默认地图得到 655 栋普通主屋与 5 个院区体块，62 处共墙关系。合计城内 159 个、城外 501 个体量。854 个普通宅地中 199 个未通过放置条件，记录建筑带、通院、面宽或高差等原因。其他地图种子的成功数和可选院区部件数量不同。

27,560 项数据检查通过，覆盖三组地图种子、共墙与通院、斜临街面、孔洞和分离建筑带、基础高差、建筑/屋顶相交、入口归属、网格投影与高度、法线和顺时针三角形方向、复现、取消与版本变化。完整图形流程检查通过实际视口输入验证按钮和屋顶点选，并验证四层显示、局部重跑、两个可选开关及所有上游的失效与重建。
