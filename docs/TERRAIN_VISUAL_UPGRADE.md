# 演示场景地形视觉升级方案

日期：2026-11-04。状态：A、B 阶段已实施；C、D 保留为后续方案。实现、运行方式和验收记录见[地形视觉 A / B 实施与验收](TERRAIN_VISUAL_AB.md)。下文保留总体设计及其目标预算。

## 1. 目标与美术方向

把现有温带河谷从均匀色块的程序化底图，提升为具有草甸、林地、河滩和人类活动痕迹的区域景观。全图能读懂河谷与城镇结构，区域视角能辨认地表类型，近景能看到材质和自然过渡。

建议沿用现有简化建筑和树木的造型语言，采用**低饱和、适度风格化的温带田园**：初夏草甸、灰褐土地、深橄榄色林下、灰青河水，配合偏暖日光与偏冷环境光。材质细节保持克制，与当前建筑体量的精细程度一致。

首版范围是地表、河岸、水面、自然植被和地面接缝。保留 2 × 2 公里范围、真实米制高程、固定种子和六个 PCG 节点；视觉参数不改变建设适宜性、道路占地和地块划分。建筑正式美术、城墙建模、侵蚀模拟、地形重塑和第一人称漫游另行安排。

## 2. 当前依据与主要问题

本方案检查了当前源码及已有的 `placement_overview.png`、`placement_market.png`、`river_forest_detail.png`。这些截图用于判断现状；本次没有重新运行渲染或测量性能。

| 当前实现 | 画面影响 | 升级重点 |
| --- | --- | --- |
| `MapRenderer.SetView` 以顶点颜色混合草甸、林地和河岸，无地表纹理 | 大片浅黄绿地面缺少尺度与材质变化 | 分层地表着色，建立宏观色斑、中尺度斑块和细节三个层级 |
| 默认 384 × 384 单元，网格间距约 5.21 米 | 足以表达缓坡，无法靠顶点颜色表达细小土斑和湿边 | 保留网格，优先提升像素级材质 |
| 河岸着色使用名义河宽，实际河宽沿程变化 | 河岸过渡不能准确跟随局部水陆关系，截图中呈均匀浅色边 | 依据局部水位、真实地表和局部河宽构建湿岸 |
| 河水使用世界坐标正弦颜色波纹，未构建沿河流向 UV | 水面接近青色带，波纹缺少随弯道流动的方向 | 深浅分区、沿河流向扰动、适度反光 |
| 三种程序树形，每种一个全图 MultiMesh | 林地缺少灌木与林缘层次，近景树形重复 | 小幅丰富树冠，增加有分布规则的低矮植被 |
| 道路、院落、田地共用顶点色地面，田垄使用线段 | 色块拼贴明显，耕作线具有诊断图观感 | 按用途分组材质、边缘融合、耕作纹理 |
| 正交相机，滚轮修改 `Size`，相机距焦点固定约 3400 米 | 以相机距离决定近景细节会失效 | 按投影尺寸与屏幕覆盖选择细节 |

## 3. 按观看尺度设计

以下 `Camera.Size` 阈值是初始调参值，最终以投影像素大小和实际视口校准。切档增加约 10% 的滞回区间，防止滚轮缩放时反复跳变。

| 观看尺度 | 初始 Size 范围 | 应看到的内容 | 应收敛的内容 |
| --- | --- | --- | --- |
| 全图 | 1800–3600 米 | 河谷走势、连续林块、草甸明暗、城镇与田园边界 | 细小草丛、碎石和高频水纹；远处田垄合并为方向性色调 |
| 区域 | 450–1800 米 | 林缘灌木、湿岸、土路路肩、耕地与草地差异 | 单株草叶和细碎表面凹凸 |
| 近景 | 120–450 米 | 土壤颗粒、稀疏草簇、浅滩砾石、车辙与建筑接地 | 高频纹理仍须过滤，不能出现颗粒闪烁 |

小于约 1–2 像素的细节逐渐回归平均颜色；草簇以屏幕投影尺寸和可见地面区域决定显示，不以“距离相机 100 米”之类阈值控制。

## 4. 地表：六类材质，三层尺度

首版地表 shader 使用世界 XZ 坐标，跨网格连续采样。基础材质采用同一美术风格，颜色、法线、粗糙度分别控制；控制图按线性数据读取，颜色贴图按颜色空间导入。缓坡先使用平面投射，确有拉伸问题后再局部引入三平面投射。

| 地表类型 | 分布依据 | 视觉特征 |
| --- | --- | --- |
| 草甸 | 普通非水域开阔地 | 灰绿主色，细节弱，整体保持连续 |
| 干草 | 局部较高地带与低频斑块 | 少量黄褐混色，与草甸柔和过渡 |
| 林下腐殖土 | 森林密度、实际保留树群及林缘过渡 | 暗橄榄棕、稀疏落叶，避免涂成黑色阴影 |
| 裸土 | 道路路肩、院边、耕地和少量自然露土 | 灰褐色，粗糙度较高，可复用于田地与土路 |
| 湿泥 | 局部水位以上的低岸、间断浅滩 | 颜色较深、略低粗糙度，宽度随地形变化 |
| 沙砾 | 河滩与少量冲刷位置 | 浅灰褐、细粒感，面积克制 |

材质权重由地形数据与有意义的覆盖规则生成；噪声只负责打散过渡，不能凭空制造大块“生态区”。坡度用于限制草和湿泥、增加露土；这张平原地图首版不铺大面积岩石。

三层尺度建议：

1. **宏观 80–250 米**：低对比色温与明度变化，让全图草甸有连续的大块关系，避免规则棋盘或云纹。
2. **中尺度 4–20 米**：干草、裸土、落叶斑块，优先沿林缘、河岸、路肩出现。
3. **微观 0.15–2 米**：少量颗粒、法线和粗糙度变化；随屏幕采样足迹淡出，并启用 mipmap。

建议先用 1024² 自然控制图覆盖全图，约 1.95 米/像素；它用于宽尺度过渡，不承担窄街巷和细小通道的边界。窄边界继续使用原始多边形与专用地面网格。自然细节纹理先采用 1K 规格，土路、院地、耕地尽量共享基础贴图。

## 5. 河流：先建立岸线，再改善水面

### 岸线与湿岸

岸线依据当前河面与 `HeightAt` 地表的实际相交位置建立，并限制在河道邻域；不能仅用“中心线距离减去默认半宽”。河面沿程下降，须使用对应河段的水位。

由水向陆建立“浅水 → 间断湿泥/沙砾 → 湿草 → 普通草甸”过渡。湿边宽度建议从 0.5–3 米调起，岸坡过渡从 3–12 米调起；宽度随岸坡和局部地形变化，不做连续等宽描边。砾石与芦苇只在部分适合的低岸出现，保留大片无遮挡岸线。

首版不位移地表。若放大后确认 5.21 米网格导致岸线轮廓无法接受，应另开几何升级：同步地表网格、查询接口和环境采样，再重建下游。仅增加三角形而继续采样原分片平面，不能改善原有轮廓。

### 水面

- 水面网格补充沿河累计长度与横向坐标，纹理沿局部切线缓慢移动；转弯处保持连续。
- 从河床与局部水位预计算水深，形成浅灰青、深灰蓝绿的柔和变化。弯道、交叠水面和地图两端单独检查。
- 叠加两组低幅度法线扰动，配合观察角度变化的反光；金属度归零，避免金属质感。整条平缓河流不铺白色泡沫边。
- 基础版采用不透明、深浅着色的水面，降低透明排序成本。真实折射、屏幕空间反射和体积水体不作为本轮依赖。
- 用固定时间截图比较静态构图，再用短时播放检查流向、重复纹理与闪烁。

## 6. 道路、院落与田园衔接

沿用 `ScenePlacementSet.GroundPatches` 的用途和来源，不根据最终颜色反推材质。主路、街巷使用压实土；广场与公共院地使用较浅的碎石或夯土；后园混合土与稀草；耕地使用土壤及耕作方向。

材质边界先服从原始道路和地块几何，再增加视觉过渡：草色略向路肩渗入，路中心更实，院边有轻微磨损。道路、门洞、通院通道和建筑占地内不得因噪声生成草丛。过渡只影响外观，不扩张或缩小规划占地。

现有地面合并网格只带颜色和来源 ID，单纯替换一个材质不能自动得到全部地表类型。首版按少量材质族拆成共享 surface，保留来源映射与拾取；后续需要时再改成材质索引。避免为每个地块创建独立材质。

当前地面通过采样环境网格生成，并整体抬高 0.12 米；它与原始 5.21 米地形网格并非同一网格。实施前测量覆面与原地表的高差，坡岸附近尤其要检查。若出现穿插，新增只读的渲染贴地适配器，将覆面裁切到原地形三角形并贴合，而不是不断增加抬高量。原始占地和 PCG 查询契约保持不变。

自然景观中的田垄改用沿已有 `CultivationLines` 的低对比材质条带或短条带网格，统一相位与方向；远处减弱对比，近处才显示沟纹。诊断模式保留原线条。果园在后续植被阶段沿现有种植线放置少量树冠，并裁剪到果园内部，不能重新随机散布成森林。

## 7. 植被：分布层次优先

保留现有树木位置、树种和种子作为大树锚点，先增加少量树冠轮廓与色相变化。自然细节分成林内稀疏灌木、林缘小树与草簇、河岸芦苇、田埂与路边杂草，使用各自的坡度、水位、地表和占地约束。

当前树木避让带包含树冠半径，不可把同一宽度直接用于禁草。按对象半径构建避让规则：树木继续服从树冠间距，草簇和碎石依据道路、建筑、设施、出入口及保护通道的真实形状检查。林下暗色与植被同步清理，避免城镇建成后残留大片深色“森林地毯”。

自然细节采用稳定的“地图种子 + 区块坐标 + 类别”种子，跨区块分布不受加载顺序影响。只生成可见区及一圈预取区，离开后缓存或释放；草簇使用不透明简模或裁切材质，避免大量透明叠加，默认不投射阴影。

树木与地表细节按空间区块组织 MultiMesh，初始区块边长可比较 125 米与 250 米。MultiMesh 的裁剪以整体为单位，分区可避免一个全图包被局部视野持续绘制；分区也会增加提交次数，须用实际帧耗时决定粒度。[Godot 4.7 MultiMesh 文档](https://docs.godotengine.org/en/4.7/tutorials/performance/using_multimesh.html)

## 8. 光照与展示

保留一盏方向光，日光仰角先在 30–40° 内调试，让缓坡、树冠和屋基有稳定体积感。降低地面黄绿的饱和度与高亮程度，环境光维持中性偏冷；先校准材质和曝光，再决定是否需要额外环境效果。

当前阴影最远距离为 4500 米，相机距焦点约 3400 米。不能直接套用近景游戏的 100–300 米阴影距离，否则地面可能落在阴影范围外。应根据当前相机空间中的可见地面深度调整级联覆盖，并在低俯角、全图与近景检查阴影清晰度和跳变。

项目继续使用 Compatibility。官方 4.7 功能表列出基础雾和 SSAO 支持，但 Decal、SSR、体积雾不支持；SSAO 作为本机验证后的可选增强，基础效果以材质、灯光和几何为准。路肩使用 shader 权重或贴地网格，不依赖 Decal 节点。[Godot 4.7 渲染器功能表](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html)

演示默认保持画面通透；雾只在低角度镜头少量使用，不能掩盖地形问题。地图外缘保留沙盘式切边，减少边缘明暗抢眼程度。增加自然景观的“简洁 / 标准 / 细节”预设，以及隐藏面板的截图入口；既有高程、坡度、适宜性与 PCG 诊断图层使用原有清晰配色，隐藏新增草簇和材质细节。

## 9. 实现结构与失效规则

建议增加独立的视觉层，作为原始地图和已生成城镇结果的消费者，避免进入“环境采样 → 城镇生成”的依赖链。

| 建议文件或组件（尚未创建） | 职责 |
| --- | --- |
| `scripts/terrain/TerrainVisualSettings.cs`、`configs/terrain_visual.tres` | 配色、材质尺度、湿岸、细节密度与质量预设 |
| `scripts/terrain/TerrainVisualData.cs` | 自然材质权重、岸线、水深和渲染缓存版本 |
| `scripts/terrain/TerrainVisualBuilder.cs` | 从只读地图数据生成基础视觉控制场 |
| `scripts/terrain/TerrainSurfaceOverlay.cs` | 接入有效道路、田园和场景地面，生成材质覆盖及分类避让 |
| `scripts/terrain/TerrainDetailRenderer.cs` | 空间分区、稳定散布、屏幕尺度控制和资源释放 |
| `shaders/terrain.gdshader`、`shaders/ground_surface.gdshader` | 自然地表与人工地面的分层着色 |
| 现有 `river.gdshader` 与 `MapRenderer` | 河水与沿河坐标、材质切换、基础绘制装配 |

依赖按以下顺序更新：原始地图 → 自然控制场 → 当前有效城镇覆盖 → 植被避让和细节。没有城镇结果时自然景观必须独立显示。

- 修改色彩、纹理尺度和灯光：仅刷新视觉参数，不让六个 PCG 节点过期。
- 修改视觉细节密度：仅重建受影响的细节区块，不改变 `Forest` 原始环境数据。
- 修改道路或场景布置：移除旧版本覆盖，再重建相关地面与避让；只接受匹配原始地图版本的结果。
- 重建地图：清理全部旧视觉缓存；异步工作完成时核验版本，丢弃过期任务。
- 隐藏场景布置或切换节点：遵循现有预览显示规则，同步移除对应覆盖及避让，不留下不可见城镇的残留草地缺口。
- 切换诊断图层：切材质和显示状态，尽量复用网格。当前 `SetView` 每次重建地形 ArrayMesh，可在这一步调整为基础网格与诊断颜色缓存。

## 10. 实施顺序

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| A：地表与色调 | 固定基线镜头、六类自然地表、三层尺度、材质预设、灯光校准 | 全图不再呈均匀浅绿色；近景无明显重复块；诊断模式一致 |
| B：河岸与河水 | 实际岸线控制、水深着色、沿河流动、间断湿岸和浅滩 | 河岸宽度自然变化，水流跟随弯道，河口无外溢或断裂 |
| C：城镇地面融合 | 道路/院落/田园材质、路肩过渡、覆面贴地检查、田垄替换 | 城镇地面具有相同材质尺度；保留窄通道；低角度不浮地、不穿插 |
| D：自然细节与优化 | 分区树群、林缘灌木、草簇、芦苇、果园树、质量档位 | 分布稳定、占地避让正确；缩放无明显闪烁或突然成片消失 |

**推荐首先完成 A + B，作为第一轮可见成果。** C 在同一轮材质标准下衔接城镇；D 建立在地表和岸线已经成立的基础上。每阶段都保留简洁预设，便于同镜头比较和回退。

## 11. 性能目标与验收

以下为待测预算，不是当前性能结果。先在本机、同一渲染器、1440 × 900、固定种子和同一相机路径下建立基线，预热后记录至少 30 秒的中位数与 P95 帧耗时、绘制调用、三角形、CPU/GPU 时间及资源内存；记录 VSync 和硬件信息。

建议标准档的新增视觉资源以 **128 MiB** 为首轮上限，按真实格式、mipmap 和实际加载量统计；近景新增草簇、芦苇和小石合计先限 **2 万实例**，默认不投影，预算不能代替 GPU 测量。场景稳态中位数与 P95 帧耗时相对基线增加尽量控制在 **20% 内**；若基线已能稳定 60 FPS，则升级后仍以 P95 不超过约 16.7 ms 为目标。未达目标时依次降低细节密度、微观法线、可选环境效果，再检查区块与材质提交成本。

视觉缓存生成时间与完整地图生成时间分开记录；贴图不在逐帧循环中重建。反复重建后资源使用应趋于稳定，无持续累积。

固定验收视角：

| 镜头 | 主要检查 |
| --- | --- |
| 全图斜俯视 | 河谷、林地与城镇主次，宏观纹理连续性 |
| 全图正俯视 | 材质分布是否合理，农田与道路可读性 |
| 河流内弯、外弯近景 | 湿岸宽度、沿程水位、芦苇与水面关系 |
| 林缘近景 | 树冠重复、林下与草甸过渡、灌木密度 |
| 城门外道路与田园 | 路肩、田垄、林地清理和道路占地 |
| 市场与院落 | 覆面贴地、材质尺度、建筑接地、通道净空 |
| 低俯角与地图河流两端 | 网格穿插、浮地、岸边轮廓、水面边界与阴影 |

每个视角保存同相机、同种子、同灯光、同动画时间的前后截图。另执行缩放、绕转和短时水面播放，静态截图不能证明运动时没有闪烁。

数据与行为验收：

- 默认种子与现有回归种子验证；至少覆盖无森林情况及当前有效范围内的不同河宽。
- 仅修改视觉参数时，原始高度、坡度、水域、森林与适宜性数据，以及六个节点结果均不改变。
- 固定种子重复生成的散布一致；新增细节不落入水域、建筑、道路、门洞和保护通道，分类避让规则可追溯。
- 连续切换图层、质量、显示开关和地图种子，无旧纹理、旧覆盖、旧草簇残留；取消或丢弃过期视觉任务有效。
- 检查分块接缝、岸线、窄通道、纹理过滤和内存释放。控制图的分辨率不能使几米宽通道消失。

现有 `.\tools\project.ps1 test` 用于回归地图及城镇数据；`.\tools\project.ps1 capture` 与 `capture-placement` 可作为截图入口。视觉参数独立性、细节约束和新增镜头需要补充对应检查；现有测试通过不能代替地形视觉验收。
