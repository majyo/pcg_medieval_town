# 简单节点式 PCG 框架

> 2026-11-08 道路阶段调整设计见 [道路系统三阶段设计](ROAD_SYSTEM_DESIGN.md)：道路规划 → 地形平整 → 道路生成。该变更尚未实施；下文节点表描述旧实现，实施时再同步注册与接口。

更新日期：2026-11-06  
状态：环境采样至场景布置的七个固定节点（含 03B 道路竖向与地形修整）已实现独立运行、状态管理、取消和预览；通用图定义、执行器和图编辑器尚未实现。适用于当前 Godot C# 项目。

## 1. 核心决定

**图连接完整的生成阶段，每个节点根据固定输入、参数和种子，一次生成完整结果。节点是独立开发、调参、运行和查看结果的单位。**

每次运行从输入重新计算当前节点，成功后发布结果并结束。后续改参或换种子时重新生成，已有有效的上游结果直接复用。节点内部用普通 C# 实现采样、搜索、几何处理和有限次数的优化；这些计算都服务于本次输出，不保存可续跑的城市发展状态。

首版采用小型、有向无环的数据依赖图（DAG），顺序执行。PCG 节点是 C# 生成模块，不要求继承 Godot `Node`；画布上的节点只是编辑视图。Godot 场景节点继续负责界面与展示。

节点拆分依据是**是否有值得独立调参和预览的稳定结果**。例如道路网络可以单独查看与重跑，路径搜索和交叉口处理则属于道路节点内部。

**框架范围是城镇 PCG。基础地图、地形、河流和自然植被由管线外准备；管线通过环境采样节点读取已有环境。**

## 2. 节点边界

```text
预设环境（管线外）
    ↓ 只读输入
环境采样 → 聚落布局 → 道路生成 → 道路竖向与地形修整 → 街区与地块 → 建筑生成 → 场景布置
```

上面表示主要顺序，实际数据依赖以表格为准。采样结果直接连接需要它的节点，无需逐级转交。业务算法详见 [城市一次性生成方案](CITY_GENERATION_PLAN.md)。

| 节点 | 数据输入 | 一个主要输出 | 节点内部职责 |
| --- | --- | --- | --- |
| 环境采样 | 外部预设环境的只读查询源 | `CityEnvironmentData` | 采样高程、坡度、水域、植被及静态建设限制 |
| 聚落布局 | 环境采样结果 | `SettlementLayout` | 确定建设范围、核心、对外入口和设施预留位置 |
| 道路生成 | 环境采样结果、聚落布局 | `RoadNetwork` | 主次道路布局、地形避让、交叉口、路宽及连通性检查 |
| 道路竖向与地形修整 | 道路网络、原生只读地形 | `RoadGrading` | 竖向求解、挖填边坡、修整地形和问题登记 |
| 街区与地块 | 道路竖向结果（含道路及环境引用） | `ParcelLayout` | 街区提取、用途分配、地块细分、临街关系及退界 |
| 建筑生成 | 环境采样结果、地块 | `BuildingSet` | 按地块用途选择类型、生成体量、朝向、落地与占地检查 |
| 场景布置 | 环境采样结果、聚落布局、道路网络、地块、建筑 | `ScenePlacementSet` | 资源引用与变换、道路及设施表现、装饰物放置和避让 |

参数在各节点面板配置，例如聚落范围、道路间距、地块尺寸和建筑风格。资源库等配置以明确的资源引用表达。预览图层、相机状态与画布位置属于显示设置。

聚落布局首版限定为圆形规划范围内的单核心布局，输出实际区域、出入口与核心广场；详细职责、数据和分层预览见 [聚落布局节点](SETTLEMENT_LAYOUT_NODE.md)。

道路节点消费实际纳入区域、固定核心与入口，并将可通行广场纳入连通检查；主次路生成、路宽占地和拓扑契约见 [道路生成节点](ROAD_GENERATION_NODE.md)。

### 环境采样的边界

详细实现与验收见 [第一个节点：环境采样](ENVIRONMENT_SAMPLE_NODE.md)。输入适配器提供来源 ID、修订号及只读查询接口；输出独立的 `CityEnvironmentData`。默认目标间距为 10 米。

节点结合水域、坡度、禁建区与固定障碍得到“候选、受限、未知”状态。候选只表示当前采样精度下未发现普通地面建设限制，后续道路和地块仍需检查自己的几何约束。越界区域保持无效，缺少可选层明确记录为未提供。

采样不使用城镇随机种子。修改采样范围或精度只重新读取环境；重跑城镇流程不改变地图。现有 `TemperateMapData` 通过 `TemperateEnvironmentSource` 适配，不向下游暴露可写数组、列表和地图设置。

## 3. 节点契约

| 项目 | 约定 |
| --- | --- |
| 类型标识 | 稳定的代码注册名，例如 `road_network` |
| 参数 | 明确类型的参数对象；编辑侧可用 Godot `Resource` 保存 |
| 输入 | 少量命名且有类型的数据端口；每个必需端口绑定一个上游输出或命名外部输入 |
| 输出 | 一个明确类型的完整结果，可包含多组相关数据并供多个节点消费 |
| 执行 | 固定输入快照、参数快照和有效种子，计算、检查并返回完整结果 |

每个节点实例有持久 ID、独立参数和结果。改显示名、移动位置不改变 ID；复制节点生成新 ID。

下面是拟定的业务接口形状，尚未加入代码：

```csharp
Task<RoadNetwork> GenerateAsync(
    CityEnvironmentData environment,
    SettlementLayout settlement,
    RoadSettings settings,
    PcgContext context);
```

适配层解析端口后调用强类型业务方法。节点只读取声明的输入，不查询其他节点内部数据，不将上次输出作为隐式输入。一次调用完成当前节点的全部计算；有界搜索、分段让出和进度上报不改变一次性生成语义。

现有 `PcgContext` 提供取消信号与进度让出回调。接入通用执行器时，可按需要增加有效种子和日志；上下文不提供任意节点查询、场景树访问或隐式共享世界状态。

环境通过 `Run(graph, externalInputs)` 显式绑定。图保存输入名和类型等绑定描述；活动场景对象由宿主在运行前重新绑定。

### 数据规则

- 输入与已发布输出按只读快照使用，当前节点的临时工作数据不外泄。
- 输出是领域数据；资源路径与放置变换可作为结果，实例化由展示或导出代码完成。
- 每个节点只输出自己负责的数据，消费者显式连接所需来源。
- 坐标沿用 X 向东、Z 向南、Y 向上，1 单位等于 1 米。道路、地块及设施引用使用稳定对象 ID。
- 管线只读预设环境；03B 发布独立 `GradedTerrain`，04–06 的落地与显示使用这份修整地形，02/03 的规划合法性仍读环境采样。
- 结果可附数量、覆盖面积、跳过对象及约束诊断，帮助调参；耗时不参与生成。

## 4. 最小框架组成

| 部分 | 职责 |
| --- | --- |
| `PcgGraphDefinition` | 城镇种子、节点实例、参数、连线、外部输入绑定描述和输出目标 |
| `IPcgNode` / 节点适配层 | 声明端口类型，绑定参数，调用业务模块 |
| `PcgRunner` | 检查依赖和类型，按顺序调用节点，复用结果、传播失效并处理错误与取消 |
| `PcgRunState` | 保存内存中的结果、有效性、结果修订号、执行状态、耗时和错误 |

图定义和参数可用 Godot `Resource` 保存，运行结果与定义分开。节点注册先用显式 C# 注册表。预览器根据结果类型显示内容，不进入生成核心。

沿用现有 `scripts/pcg/environment/` 与 `scripts/pcg/preview/`；通用执行器放在后续的 `scripts/pcg/core/`，业务节点随实现逐个增加。`scripts/terrain/` 继续负责管线外测试地图。先让节点可直接调用，再接图，不为未实现阶段创建空壳节点。

## 5. 执行与局部重跑

### 执行规则

1. 检查节点 ID、类型、端口、必需输入、外部绑定、目标与循环依赖。外部地图未准备好时明确报错。
2. 根据输出目标求上游依赖，按拓扑顺序逐个执行；无依赖先后关系时按稳定节点 ID 排序。
3. 检查并复用仍有效的结果；需计算的节点固定输入修订号、参数快照、外部来源及修订号和有效种子。
4. 计算完成后检查结果约束与输入是否仍有效，成功时一次发布并增加结果修订号，然后执行下游。
5. 失败或取消时丢弃当前节点的临时结果，停止本次流程。已完成且仍有效的上游、独立分支结果可以复用。

运行期间只允许一条执行任务，锁定生成参数、连线及绑定环境；相机与图层操作仍可使用。需要改参时取消当前运行，等待退出后再编辑。输入意外变化时拒绝发布并标为过期。耗时算法按固定计算量分段让出或安全地后台执行，以保持界面响应；调度时机不影响输出。

### 运行入口

| 操作 | 行为 |
| --- | --- |
| 运行流程 | 对配置的输出目标执行依赖链，只计算缺少结果或已过期的节点 |
| 运行到此 | 确保所选节点及上游有效，不执行下游 |
| 重跑当前节点 | 要求上游已有有效结果；使当前及下游过期，从输入重新生成当前节点 |
| 取消 | 结束正在计算的任务，不发布当前节点的部分结果；再次运行从该节点输入重新计算 |

以上是通用框架的拟定入口；当前已实现环境采样、聚落布局、道路、街区地块与建筑体量的独立运行与取消。节点生成完成后即可检查结果、调整参数、再运行后续阶段。

例如只修改道路间距：

```text
环境采样 [有效] → 聚落布局 [有效] → 道路生成 [过期] → 道路竖向 [过期] → 街区与地块 [过期] → 建筑生成 [过期]
```

重跑道路节点直接复用环境和聚落布局。检查道路结果后，运行流程补齐地块、建筑和布置。

### 失效与缓存

- 参数改变：当前节点及所有下游过期。
- 连线改变或删除节点：受影响的消费者及其下游过期。
- 外部环境改变：宿主更新来源 ID 或修订号，环境采样及其下游过期。
- 城镇种子改变：使用该种子的节点及其下游过期；环境采样可以复用。
- 强制重跑：开始时使当前及下游过期，失败或取消不恢复旧结果的有效性。
- 改显示名、移动画布节点、调整相机或预览图层：不影响生成结果。
- 重新载入图、重新编译或重启：清空内存结果，重新绑定环境并计算。

缓存记录输入结果修订号、外部来源及修订号、参数修订号和有效种子。参数编辑通过统一入口通知执行器；每次运行也检查签名是否匹配。首版使用内存缓存。

旧结果可保留供对照，但明确标为“旧结果”，不作为有效输入。预览绑定结果修订号，避免将旧道路与新地块组合为当前结果。

## 6. 可重复性与验证

使用随机数的节点以“城镇种子 + 节点实例 ID”通过固定算法派生有效种子，也可显式覆盖。节点内部需要多个随机流时，用稳定名称进一步派生，避免依赖执行顺序或进程相关的 `GetHashCode()`。

每次生成从相同有效种子初始化随机流。同一代码、引擎版本、输入和参数应重现相同结果，与之前运行次数、相机操作或界面等待时间无关。首版不承诺跨版本、跨平台的浮点完全一致。

每个节点先用固定输入直接调用业务模块，检查领域约束与预览，再接回依赖链。环境采样使用只读查询源；测试地图在测试准备阶段于管线外构建。现有无界面 Godot 验证入口继续使用。

道路节点负责检查连通、交叉口和地形限制，地块节点负责检查重叠、退界与临街关系。通用执行器负责依赖、失效、发布和取消规则。

## 7. 编辑与预览

界面由流程列表或节点图、所选节点参数和结果预览组成。节点显示名称、端口、状态与耗时；先使用固定流程和参数面板，后续再加入可编辑画布。

| 所选节点 | 预览内容 |
| --- | --- |
| 环境采样 | 范围、网格、高程、坡度、水域、有效性与建设限制 |
| 聚落布局 | 建设范围、核心、对外入口与设施预留 |
| 道路生成 | 道路等级、宽度、交叉口、连通关系和生成诊断 |
| 街区与地块 | 街区、用途、地块边界与临街关系 |
| 建筑生成 / 场景布置 | 建筑体量、落地、资源实例与空间冲突 |

状态区分“未运行、运行中、有效、过期、失败、已取消”。运行中显示当前计算步骤和进度；预览显示已发布结果或明确标记的旧结果。参数编辑只标记过期，由用户显式运行。

## 8. 落地顺序

1. **已完成：环境采样独立节点。** 复用当前参数面板、只读输出、预览、取消与无界面验证。
2. **已完成：聚落布局与道路生成。** 按固定顺序直接调用，可查看范围与主次路网；每个节点可独立重跑。
   道路节点内部在路网规划后完成 [几何定型](ROAD_GEOMETRY.md)，再一次发布完整结果。几何参数同样使地块和建筑过期。
3. **街区地块、简模建筑与场景布置已完成。** [场景布置节点](SCENE_PLACEMENT_NODE.md)继承既有占地、通道与版本，完成地面、程序模型和植被避让的装配；外部美术资源适配留待后续。
4. **统一编排：最小图定义与执行器。** 接入已有节点的生成 API，完成运行流程、运行到此、结果复用和失效传播。可编辑画布随后接入同一执行逻辑。

执行器验收包括依赖缺失、类型错误、循环图、修改道路参数时复用上游、修改环境时失效全链，以及失败或取消后不发布部分结果。保存载入应保留节点 ID、参数、种子、连线和外部绑定描述。

当前优先完成可独立使用的业务节点和可见结果。子图、通用脚本语言、并行调度和跨会话缓存不属于本次框架范围。
