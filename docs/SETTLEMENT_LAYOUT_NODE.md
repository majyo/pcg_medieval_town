当前形态修订已接入：城墙/城门、公共院区、不规则街巷和前街后院。当前参数与实现覆盖范围见 [形态修订的已实现首版](MEDIEVAL_URBAN_FORM.md#已实现的首版与范围)；下文包含原始阶段的设计及验证记录。

更新日期：2026-11-03  
状态：首版已实现，接入现有地图界面。以下保留节点设计与契约；实际实现说明见文末。依赖已实现的 [环境采样节点](ENVIRONMENT_SAMPLE_NODE.md)，遵循 [一次性节点框架](PCG_FRAMEWORK_DESIGN.md)。

## 1. 职责

**把环境中的候选土地，整理成一个有明确范围、主核心和对外接口的聚落布局，交给道路节点使用。**

本节点完成四件事：

1. 根据用户指定的规划范围，筛出可用于本次聚落的土地。
2. 选择或检查一个主核心，并保留核心所在的连通区域。
3. 在区域外缘选择道路出入口，给出位置与朝外方向。
4. 为主核心预留一块公共广场，输出统计与不能使用其他区域的原因。

节点一次生成完整布局。道路走向、路宽、路网连通的最终验证属于道路节点；住宅、商业等用途分配与地块细分属于地块节点；建筑体量和资源放置属于后续节点。这里的“出入口”是未来路网的连接目标，不代表已有城门或已连通外部道路。

首版限定为**单个聚落、一个主核心、圆形规划范围、少量出入口、一块核心广场**。任意多边形绘制、多核心、教堂/城堡等设施的自动选址后续再扩展。

## 2. 输入与参数

输入端口 `environment`：当前有效的只读 `CityEnvironmentData`。节点适配层同时绑定环境采样节点的实例 ID 和结果修订号，确保修改采样精度后旧布局也会失效；原始地图来源修订号不能代替采样结果修订号。

坐标沿用 X/Z 平面，Y 为高度，单位为米。计算只使用采样快照，不重新查询原地图或修改环境。

| 参数 | 首版建议 | 用途 |
| --- | --- | --- |
| 规划中心、半径 | 初始中心取采样范围中心；半径暂定 300 米 | 直接控制期望建设位置与尺度；中心和半径保存为明确值 |
| 主核心模式 | 自动 / 手动指定位置 | 自动选址，或验证用户点选的位置 |
| 期望出入口数量 | 默认 2，允许 1–4 | 在外边缘寻找尽量分散的对外接口 |
| 出入口模式 | 自动 / 手动列表 | 手动入口全部视为必需，位置通过边界吸附工具明确选取 |
| 核心广场边长 | 暂定 40 米 | 核心周围轴对齐的正方形公共空间，预留给后续布置 |
| 最小可用面积 | 暂定 20,000 平方米（2 公顷） | 防止输出仅有核心、无法展开街道的狭小片区 |
| 有效种子 | 从城镇种子与节点 ID 派生，可覆盖 | 自动选址同分时确定稳定顺序 |

以上数值是待原型验证的起步配置，不是已测得的推荐尺度。高级评分权重、候选上限和入口分散规则先固定在配置中，首版面板只暴露上述少量参数。

修改规划中心不会同时移动手动核心或入口；改变范围后重新检查它们。自动核心也不会反过来移动规划圆。由此保持“用户指定范围 → 节点选择布局”的单向关系。

## 3. 一次生成的处理顺序

### 3.1 确定可用单元

沿用采样网格，不重新采样、不增加另一套分辨率。规划圆与采样矩形共同限定工作范围：只有**整个单元位于规划圆内，且上游状态为 `Candidate`**时才可加入候选集合。圆周截断的单元保守舍弃；越出采样矩形的区域不外推，给出覆盖不足提示。

保留排除原因：水域、过陡、禁建、固定障碍、未知、规划边缘截断，以及后续的与核心不连通。植被密度只参与选址偏好，不直接禁止建设。首版不放宽上游普通建设限制，也不另设河岸距离阈值。

对候选单元作四邻接连通分量分析，只允许共享整条单元边的连接，不允许两个角点接触即算连通。这是本次布局的静态空间检查。

### 3.2 选择主核心

自动模式在候选单元中心选址，先作硬条件筛选：核心所在分量达到最小面积，且核心广场覆盖的全部单元都合法并属于该分量。先检查可行性，再评分。

评分使用三项基本因素：较平缓、周围可用土地较多、较靠近规划中心。2026-11-08 起，平缓度使用“广场半边长 + 30 米”范围内的均方根坡度，不再只看核心所在单格；可用土地邻域为核心周围 60 米。完整数据下，平缓/空间/中心/植被权重仍为 0.35/0.35/0.20/0.10。自动选址先比较接坡风险，再以该评分和确定性种子排序：风险预估按广场及八个方向 5–50 m 的进入带，检查默认 2% 平台、2%/10 m 竖曲线以及保守 1.25/0.75 m 土方空间；它是基于规划采样的选址偏好，不代替 03B 原生地形与实际路线验收。缺少植被信息时整次运行停用该项并重新归一化，不能将未知植被视为零。手动核心不会被自动迁移；本评分是规划偏好，03B 仍须按其真实参数做严格可行性检查。

按分数降序选取，分数相同时用种子和稳定单元索引破同分。首版不以随机噪声覆盖明显的环境优劣。手动模式直接验证指定位置及其广场，失败时标出原因，不自动改到另一处。

确定核心后，仅保留核心所在分量作为实际聚落区域。其他可建片区标为“未纳入：与核心不连通”，不跨河、跨禁建区补接。连通分量只是采样尺度下的土地连接判断，不能证明指定宽度和坡度的道路一定可通过。

### 3.3 生成对外出入口

候选入口位于实际区域的**外轮廓边**，不位于内部水坑或障碍孔洞边界。入口保存边中点、邻接的内部单元、朝外方向及明确的边界边引用。

入口外侧沿边界外法线逐格检查最多三层，需有至少两层连续的候选陆地，并到达单元中心在规划圆外的位置。紧邻的一层允许是因圆周截断而未纳入的合法单元；不能穿过水域、障碍、未知或其他连通片区来满足条件。采样边界外数据不足时不能自动认可该方向，应提示扩大上游采样范围。该检查只表示附近具备陆地延伸条件，不保证通往远方目的地。

自动模式按外围开阔程度、局部坡度与入口间的角度/距离分散程度，顺序选取最多指定数量的候选；每个边界候选最多处理一次。默认最小角度间隔暂定 60°、最小空间间距暂定 60 米，均属待调试的内部规则。可用数量不足时发布实际数量与警告；一个也找不到则本次失败。

手动模式由用户在合格的边界边上点选，面板显示吸附后的准确位置；这些入口必须全部通过检查。它们不参与自动补位。道路节点把所有已发布入口作为必需连接目标。

### 3.4 预留广场并发布

以主核心为中心，保留配置尺寸的广场占地，已在核心选址时检查其合法性。广场属于公共空间：允许道路接入与通行，普通建筑地块不得覆盖。下游道路不能把它当作固定障碍，也不能因地块扣除而失去核心连接。

汇总单元掩码、核心、入口、广场与诊断，最后检查输入修订号与取消信号，成功后一次发布。任一步失败或取消，都不提供新的有效布局。

## 4. 输出 `SettlementLayout`

一个输出端口 `settlement`。以下按职责分组；实际代码以只读属性和集合表达。

| 分组 | 内容 | 下游用途 |
| --- | --- | --- |
| `InputStamp` | 采样节点 ID / 结果修订号、环境来源 ID / 修订号、参数快照、有效种子 | 检查依赖版本与复现 |
| `RequestedArea` | 规划中心、半径与期望范围 | 显示用户意图，解释边界裁切 |
| `Footprint` | 采样网格描述、只读纳入掩码、单元状态与排除原因 | 道路和地块的布局范围判断 |
| `Boundary` | 由掩码推导的外轮廓与孔洞边界、边引用 | 边界预览与入口定位 |
| `Core` | 固定角色 ID、二维位置、采样高度、自动/手动来源 | 道路的核心连接目标 |
| `Entries` | 稳定 ID、位置、高度、外向单位方向、边引用、必需连接标记 | 道路的对外连接目标 |
| `Reservations` | 首版一块广场：ID、范围、核心引用、公共空间类型、道路可通行/普通建筑禁占规则 | 地块扣除及公共空间布置 |
| `Summary` | 期望面积、实际区域面积、广场占地、剩余候选面积、入口数量与警告 | 查看结果是否符合预期 |

`Footprint` 是空间判断的权威数据；轮廓从它派生，不能独立编辑。保留孔洞，不用单一外轮廓填满水域和障碍。当前 `ConstraintPolygon` 只表示无孔简单多边形，不能直接把它当作完整聚落区域；首版使用网格掩码和边界线段就能完成逻辑与预览，避免先开发复杂多边形布尔系统。

实际区域面积为纳入单元数乘单元面积。广场在网格中按所有相交单元保守占地，报告名义几何面积与网格预留面积；剩余候选面积扣除这份网格预留。后续地块节点遵守同一预留规则。这些面积均未扣道路、地块退界及建筑覆盖率，不能换算成已实现人口或建筑容量。

可提供 `Contains(worldXZ)`、`TryGetCell(...)`、`IsReservedForBuildings(...)` 等只读查询。输入与结果不暴露可写数组；边界、点位和 ID 在相同输入与种子下稳定，不承诺参数修改后每个自动对象继续保留相同 ID。

评分热力、落选核心及入口候选只作为当前生成的调试数据，绑定相同结果修订号，不成为新的图端口，也不让下游依赖评分实现。

## 5. 如何可视化

### 默认：地形上的布局总览

复用当前三维地图与相机，提供正俯视快捷入口。只显示本节点的空间决策，图例同时使用颜色、形状和文字。

| 内容 | 表现方式 | 用户能判断什么 |
| --- | --- | --- |
| 规划范围 | 白色或中性高对比虚线圆 | 原本想在哪里、做多大 |
| 实际聚落区域 | 半透明绿色填充 + 实线边界 | 哪些土地被纳入 |
| 内部限制与孔洞 | 保留底图，受限处加红色斜线；未知用灰色网纹 | 哪些地方不能按当前数据建设 |
| 其他可建片区 | 淡灰轮廓、标注“未纳入” | 哪些土地因与核心断开而舍弃 |
| 主核心 | 金色圆环、中心点与“主核心”标签 | 城市的组织中心在哪里 |
| 核心广场 | 金色方框和透明填充 | 公共空间占多少地 |
| 出入口 | 蓝色三角形、朝外箭头、E1/E2 标签 | 将来道路从哪里出入 |

默认不连接核心和入口。可选“连接目标”图层用虚线表达道路节点应连接哪些点，明确标为“连接意图”，不沿线评估道路或显示道路宽度。

叠加面沿采样地形贴地并略抬高，避免闪烁；关键标记以屏幕可读尺寸显示。对未知地面不伪造贴地高度，改用屏幕标记说明缺失。地形、森林显隐仅影响查看，不改变布局。

### 两个辅助图层

- **限制原因**：按环境限制、边缘截断、与核心不连通等原因查看未纳入的单元。保留多原因信息；面积总计使用互斥主分类，不能直接相加多原因统计。
- **选址评分**：自动核心候选的评分热力与少量最佳候选。鼠标悬停显示平缓、可用空间、中心距离和可选植被项；手动模式显示选中位置的检查结果。

### 面板与操作

右侧面板沿用环境采样的交互模式：参数、运行/取消、结果摘要、图层开关与选中对象详情。默认摘要只显示实际面积、剩余候选面积、入口数量与问题数；网格间距在状态栏标明。

用户进入明确的“指定规划中心 / 指定主核心 / 指定入口”模式后才能点选，避免与相机操作冲突。点击列表项定位并高亮对象；点击标记显示坐标、来源、检查结果。首版不需要拖拽轮廓编辑器。

参数修改时先使当前结果和下游过期；旧结果仍可查看，明确显示“旧结果”。新参数仅显示为独立的编辑草稿，点击运行后才发布新布局。选层、悬停、相机移动与调透明度不重新生成。

## 6. 首版验收

1. 默认测试地图上产生单个有效区域、一个核心、一块广场和至少一个合法出入口；相同输入、参数和种子重复运行结果一致。
2. 河流或禁建带分割规划圆时，只保留核心所在的四邻接区域；内部孔洞保留，斜对角接触不被误判为连通。
3. 手动核心落水、越界、广场放不下或必需入口无效时给出位置和原因；不会静默移动或替换用户点位。
4. 入口不能落在孔洞、河岸或未知的采样边界上；数量不足与完全不可用有不同处理。
5. 广场可供道路连接，普通建筑不可覆盖；面积统计符合网格掩码和预留规则，明确标注采样尺度的近似。
6. 环境采样修订、布局参数或种子改变使结果过期；取消和失败不发布半成品，不修改上游环境。
7. 图层、标记、坐标和统计与正式输出一致；旧结果有明确标签；三维和俯视图都能看清核心与入口。

建议实现顺序：先完成范围掩码、手动核心与基础叠加；再加自动核心、入口和广场；最后补评分诊断与交互。先用独立 `SettlementLayoutNode` 和现有面板跑通，再接通用图执行器。

## 7. 实现与使用（2026-11-03）

- `scripts/pcg/settlement/SettlementLayout.cs`：不可变配置、只读结果、连通分量、候选评分、广场与入口规则、节点发布和失效。
- `scripts/pcg/preview/SettlementPreview.cs`：贴地单元、边界孔洞、核心广场、入口箭头、连接意图和三个图层。
- `scripts/Main.Settlement.cs`：右侧节点切换、参数面板、运行取消、地图点选、悬停详情与版本联动。
- `scripts/pcg/settlement/SettlementValidation.cs` / `scripts/Main.SettlementValidation.cs`：无界面契约验证与真实渲染交互验证。

先运行环境采样，再切换到“02 聚落布局”并独立生成。手动入口为空时自动生成；进入添加入口模式后点选有效区域外缘，系统明确吸附到合格边中点并填入坐标。修改规划或核心参数后，先重新生成再选择入口。清空手动入口恢复自动模式。面板滚动查看预览与摘要，参数本次会话有效。

当前边界保存为带外缘/孔洞标记的网格边段，权威区域仍为只读网格掩码。广场覆盖按网格保守预留，输出中明确允许道路通行。颜色实现采用绿色区域、金色广场、蓝色入口，排除原因图层使用色块；未知地面不绘制伪造的贴地面。调试评分保存分项并在悬停时显示，未增加独立的最佳候选列表和对象列表控件。标记可在地图点击查看位置，界面不提供自由多边形编辑。

`.\tools\project.ps1 test-settlement` 写入 `artifacts/settlement_validation.json`；`test` 同时检查地形、采样和布局；`capture` 执行引擎内控件回调及视口输入验证，并保存三层布局截图。此验证不等同于实体鼠标键盘测试。10 米环境网格只提供宏观判断，实际道路宽度与通行仍需后续道路节点验证。

验证结果：C# 构建零警告、零错误；布局无界面检查 20 项通过，默认地图实际区域 140,100 平方米、2 个入口。已有三组地形与 40 项环境采样检查通过。真实渲染验证覆盖参数默认值、三个图层、地图点选核心、入口吸附、局部重跑、取消、采样和地图失效联动；三层截图已检查。
