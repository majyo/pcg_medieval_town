# 道路竖向、地形修整与正式路面方案（历史记录）

方案日期：2026-11-06。状态：**G1–G4 功能已实现，数据/界面/导出验收通过；性能绝对值与显存达标，相对增幅目标尚有小幅差距**（G1 历史记录见第 14 节，本次交付见第 15 节）。依据当前 `RoadNetwork` / `RoadGeometry`、`TemperateMapData`、`SceneAssembler`、`CityGroundMesh` 的实际接口编写，遵循 [一次性节点框架](PCG_FRAMEWORK_DESIGN.md)。

> 修订（2026-11-06）：初稿采用“只填不挖、不写地形、路面边界等于原地形”。该前提下路面只能跟随原始地形起伏，无法做到“横向平整、纵向只有长程变化”，已废弃。本版改为：**道路先做竖向设计，再把设计面写入地形**，下游全部基于修整后的地形。

## 0. 结论

正式道路分两部分，职责不同：

1. **新增规划节点“03B 道路竖向与地形修整”（`road_grading`）**：位于 03 道路之后、04 地块之前。为每条路段、路口、广场和城门通道求出平整的设计面，再按挖填边坡把设计面写入一份**修整后地形** `GradedTerrain`。04–06、地形渲染、植被和城防显示全部改为从这份地形取高度。
2. **正式路面构建放在最终装配阶段**：由 03B 的设计面派生路面网格、材质、碰撞、导航和道路图。它不影响任何高度，只改它的参数不会让规划结果过期。

```text
01 环境 → 02 聚落 → 03 道路（选线 → 平面定型）
        → 03B 道路竖向与地形修整（设计面 + GradedTerrain）
        → 04 地块 → 05 建筑 → 06 场景布置
        → 装配：修整地形网格 + 正式路面 + 碰撞/导航 + 建筑/附属物 → GeneratedTown / 导出
```

## 1. 道路的竖向要求

| 要求 | 含义 |
| --- | --- |
| 横向平整 | 截面为直线加 1.5–2% 横坡（土路中间高，卵石街向中央排水沟），不随地表横向起伏 |
| 纵向只有长程变化 | 纵断面是平滑曲线：受最大纵坡和坡度变化率限制，短于约 20 米的起伏被消除 |
| 路口与广场平整 | 路口为单一平面（坡度 ≤ 3%），广场为平面（坡度 ≤ 2%），进入的路段在过渡段内接顺 |
| 地形服从道路 | 路面范围内地形等于设计面；路外按挖方/填方边坡过渡回原地形 |
| 有界修改 | 挖深、填高、边坡宽度都有上限；水域、城墙等锁定区域不改 |

平面仍以 03 的 `Geometry.Area / Surfaces / Boundaries` 为准，03B 不移动道路、不改路宽。需要改走向时回到 03。

## 2. 为什么放在 03 与 04 之间

- **高度是下游的输入**：地块的地形统计、建筑基础 `BaseY` 与落地高差、附属物落地、院地和田园地面都要读高度。写入地形会改变这些高度，所以必须在 04 之前发布，且 03B 重跑必然使 04–06 过期——这是正确的失效，不能回避。
- **不并入 03**：竖向参数（平滑尺度、边坡）调整频繁，独立成节点可复用 03 的选线和平面定型，不重跑路径搜索。
- **路面网格不进 03B**：网格、材质、碰撞、导航只是设计面的派生表达，放在装配阶段。改材质、分块、细节等级不让任何规划节点过期。

| 变化 | 03B | 04–06 | 装配 |
| --- | --- | --- | --- |
| 地图 / 环境 / 聚落 / 03 重跑 | 过期 | 过期 | 过期 |
| 03B 竖向参数 | 过期 | 过期 | 过期 |
| 04–06 参数 | 不变 | 按原规则 | 过期 |
| 路面材质、细节、碰撞/导航开关 | 不变 | 不变 | 仅重建 |

| 来源 | 用途 |
| --- | --- |

## 4. 竖向设计

### 4.1 求解顺序

全部为有限的确定性计算，每一步都有预算。以下为 G1 实际采用的做法。

1. **广场平面**：对广场范围内每 2 米的原生地形做最小二乘平面拟合，坡度超过上限时按比例压到上限（保持平均高程）。
2. **节点高程**：每个拓扑节点取原生地形在半径 0.75 × 平滑尺度（默认 15 米）内的平均高程，夹在挖深/填高上限内。区域入口（地图边界）固定为原地形；位于广场内的节点取广场平面高程。随后有限轮检查每条路段两端高差是否超过 0.9 × 最大纵坡 × 路长，超过则把非固定端拉近。
3. **广场接近约束**：距广场 30 米以内的节点和纵断面站点，高程限制在 `广场平面 ± 0.5 × 最大纵坡 × 距离` 内，保证道路爬到广场边缘；与挖填上限冲突时广场约束优先。
4. **路段纵断面**：沿定型中心线每约 1 米设站点，取原地形高程 `t(s)`。
   - 目标线：以 σ = 平滑尺度 / 2 做高斯平滑，再加线性修正使两端等于节点高程。
   - 约束：两端固定；纵坡 ≤ 03 的最大纵坡；每 10 米纵坡变化 ≤ 2%；每站 `−最大挖深 ≤ z − t ≤ 最大填高`；门道范围内二阶差分为 0（直线纵坡）。
   - 求解：在上述盒约束下求与目标线最小二乘最接近的纵断面（ADMM，五对角带状矩阵），再做一轮投影使硬约束精确满足。纵坡和挖填上限是硬约束；坡度变化约束无解时，只在阻碍求解的站点前后 10 米内逐步放宽（每轮 ×4，最多 16 轮），并发布“坡度变化放宽”提示。硬约束无解时节点失败，提示该路段与挖填上限。
5. **横断面**：土路为路拱（中间高），城内市场街与城门街为中央排水沟（中间低），横坡默认 2%，超出半路宽的部分不再继续变化。
6. **路口平台**：取进入路口的各路段在离开路口面片处的三点截面高程，拟合一个平面，坡度 ≤ 3%。相距不足过渡长度（4 米）的路口合并为同一平台，避免相邻平台之间出现台阶；位于广场内的路口直接使用广场平面。

结果是定义在 `Geometry.Area ∪ Plaza` 上、连续且可直接查询的**设计高程函数** `RoadGrading.TryDesignHeight(p)`：

- 路段扫掠：中心线每 0.5 米一个采样点，各自给出“该站点设计高程 + 该点相对其切线的横坡偏移”，按距离高斯加权（σ = 1.5 米）平均。直线和圆弧上等于精确的垂直截面；在急弯内侧、或同一路段从自身旁边经过时，只是混合相邻高度，不会因投影跳到另一支而出现台阶。
- 相邻路段：过渡长度内的所有路段扫掠按 `(1 − d/T)²` 权重混合，权重只取决于到各面片的距离，所以接缝两侧取值一致。
- 路口与广场：以紧支撑 Shepard 权重混入，距离为 0 时精确等于平台或广场平面。

### 4.2 写入地形：坡度受限包络

固定区域 F 包括两类：道路/广场（高程 = 设计面）和锁定区（水域、河岸缓冲、城墙基础，高程 = 原地形）。其他位置的修整后高程为：

```text
上限 U(p) = min over q∈F ( z(q) + 挖方坡率 × 距离(p,q) )
下限 L(p) = max over q∈F ( z(q) − 填方坡率 × 距离(p,q) )
修整后 h(p) = clamp( 原地形(p), L(p), U(p) )
```

- 道路低于原地形时，两侧地面被 U 压下，形成挖方边坡；道路高于原地形时，被 L 托起，形成填方边坡。离开道路足够远后 U、L 都不再起作用，地形回到原样。
- 默认挖方坡率 1:1、填方坡率 1:1.5。影响宽度随挖填量自动确定：最大挖深 1.5 米时边坡最宽约 1.5 米，最大填高 1.0 米时约 1.5 米。
- 多条道路、广场、锁定区同时生效，结果确定且与处理顺序无关。U、L 用栅格上的距离传播（有界 Dijkstra）计算。
- **冲突**：若某处 L > U，说明两个固定区域高差超过边坡能消化的距离（例如两条相距 3 米、高差 2 米的道路，或道路边紧贴河岸）。先回到 4.1 第 2 步收紧相关站点的上下界重解；仍冲突时记录为“需挡土墙”位置，用垂直台阶处理，并在装配阶段放置简化石砌挡墙。不静默修改锁定区。

边坡会进入路边地块的前部。这是中世纪街道的真实情况：临街房屋与街面同高，后院保留原地形。05 建筑改从修整后地形取高，基础自然落在街面高程附近。

### 4.3 超限与诊断

| 情况 | 处理 |
| --- | --- |
| 纵断面在挖填上限内无解 | 局部缩短平滑尺度重试；仍无解则节点失败，提示调整 03 的路线或坡度参数 |
| 路口拟合平面坡度超过 3% | 保留原坡度并发布注意事项，不移动路口 |
| L > U 冲突 | 收紧纵断面后重试；仍冲突则记录挡土墙位置 |
| 边坡需要修改锁定区 | 不修改锁定区，按冲突处理 |
| 平滑后纵坡超过上限 | 不允许发布；由约束保证不会出现，验证时复查 |

## 5. 修整后地形的表示与渲染

### 5.1 数据

`GradedTerrain : ITerrainSurface`，只读，带指纹与修订号：

- **查询高度** `HeightAt(p)`：p 位于道路或广场内时直接返回设计高程（精确）；否则返回 `原地形 + 修整差值`。
- **修整差值栅格**：0.5 米间距，按 64 米分块稀疏存储，只保存存在差值的分块。
- **统计**：挖方/填方体积、最大挖深/填高、受影响面积、挡土墙位置。

下游所有“落地高度”统一调用 `ITerrainSurface`。目前约 40 个文件分别直接调用 `CityEnvironmentData.TryHeightAt`（10 米规划采样）或 `TemperateMapData.HeightAt`（原生地形），需要区分清楚：

| 用途 | 高度来源 |
| --- | --- |
| 规划合法性（02 选址、03 选线坡度、环境限制） | 保持 `CityEnvironmentData` |
| 落地与显示（建筑基础、附属物、地面网格、城墙示意、树木、相机贴地） | 改用 `GradedTerrain` |

### 5.2 地形网格

- 与修整栅格相交的地形区块，在区块内按 0.5–1 米重建网格，高程取 `原地形 + 差值`；其他区块保持原 5.2 米网格。
- **无裂缝**：修整区域外缘一圈差值强制为 0，且精细区块的边界落在原网格线上。原网格三角形沿网格线是线性的，精细区块边界顶点正好落在粗区块边上，因此不会产生 T 形裂缝。
- 道路范围内，地形高程压到设计面以下 3 厘米，由正式路面覆盖；道路边缘外保留一格与路面同高的路肩，路面网格外缘加 0.15 米向下的裙边，遮住两套网格之间的缝隙。
- 地形材质增加“边坡”掩膜：挖方露土、填方压实土，按差值大小与地形自然材质混合。
- **树木**：树冠范围与“差值超过 0.1 米”的修整区相交的树移除；其余树按修整后高程重新落地。原始树木列表保持只读，与现有植被掩膜机制一致。
- 河流与水面位于锁定区，不受影响。

## 6. 正式路面（装配阶段）

由 `RoadSceneBuilder` 读取 03B 结果生成，归属 `GeneratedTown/Roads`。

| 项目 | 做法 |
| --- | --- |
| 三角化 | 路面面片按 0.5 米网格裁切，顶点高度取 `RoadDesign.HeightAt`。设计面连续且足够平滑，T 形顶点处误差在毫米级，验证中限制在 5 毫米内 |
| 铺装分类 | 广场、门道为石铺；城内的市场街、城门街为卵石加中央排水沟；城内其他街道和城外街带为压实土路；后巷为窄土巷；城外其余路段为车辙土路。路口继承相连道路的最高等级。分类表放在 `configs/road_construction.tres` |
| UV | 路段面片：u = 沿中心线弧长，v = 横向位置 / 宽度；路口、广场：世界平面 UV |
| 材质 | 单个 `shaders/road_surface.gdshader`，按铺装类型从纹理数组取样，边缘向地形过渡；材质键形如 `builtin/road/cobble-v1`，便于外部资源替换 |
| 分区块与细节 | 128 米区块；远景用 2 米网格裁切，`VisibilityRange` 切换 |
| 碰撞 | 每块一个 `StaticBody3D` + `ConcavePolygonShape3D`（路面）；修整后地形另用分块高度图碰撞 |
| 导航 | 由路面三角形直接构造 `NavigationMesh`，不烘焙；广场、门道并入；门口到临街边用 `NavigationLink3D` 连接 |
| 道路图 | 导出 `RoadRuntimeGraph`：三维中心线、宽度、铺装、坡度、入口/城门/核心锚点 |
| 挡土墙 | 在 4.2 记录的冲突位置生成简化石砌挡墙 |
| 拾取 | 三角形保留 `RoadId / NodeId / 铺装类型` 来源 |

装配时检查 03B、06 引用的是同一个 `RoadNetwork` 和同一份 `GradedTerrain`；不一致时提示过期，不混合显示。`export-town` 把 `GeneratedTown`（修整地形区块、路面、碰撞、导航、建筑、附属物）存为 `res://generated/town_<种子>/` 下的 `.tscn` 与 `.res`，并附各节点修订号清单。

## 13. 风险与后续

- **03 选线未考虑横坡**：03 只检查纵坡和地表坡度上限，可能选出横坡大、需要大量挖填的路线。若 G1 统计显示挖填偏大，在 03 搜索成本中加入“横坡 × 路宽”的估算挖填代价，属于 03 的改进。
- **规划采样与修整地形的差异**：02/03 的合法性判断基于 10 米采样，修整后的实际地形可能与之不同。03B 用设计面重新检查纵坡，下游落地检查使用修整地形，两者分工明确。
- **性能**：精细地形区块只覆盖修整区域；道路遍布 2 公里范围，需在 G2 实测内存与三角形数，必要时将城外车辙路的平滑尺度和修整精度设为较低档。
- **桥梁与深路堑**：桥梁仍待 03 的显式桥位；超过挖深上限的路堑、下沉门道需要挡土墙或独立结构，暂只登记位置。

### 地形写入

- `GradedTerrain` 保存原地形加差值，不修改 `TemperateMapData` 或原树木列表。道路与广场高度查询直接返回设计面，路肩用平滑权重接入差值栅格，消除边缘查询跳变；锁定区始终返回原高度，墙体轮廓使用 1 mm 保守查询容差吸收裁切坐标的浮点误差。
- 实际采用**有限半径内的精确欧氏距离包络**，替代原方案的栅格 Dijkstra。默认边坡范围很小，局部计算可避免八邻域距离方向性；输出与线程调度、源处理顺序无关。搜索半径和栅格节点总数均有预算，超限失败，不发布部分结果。
- 稀疏块为 **64×64 个栅格节点**（默认 0.5 m 精度时边长 32 m），保存固定源、修整差值和角色。指纹涵盖原生高度、竖向参数、道路中心线、纵断面及差值节点内容，节点修订号由 03B 状态对象维护。
- 水域/河岸、非门洞城墙基础锁定；道路设计直接侵入锁定区时明确失败。边坡冲突先按邻近锁定源/其他道路收紧相关纵断面站点上下界，有限重试一次；不能改善时保留原可行设计并登记挡墙，不修改锁定区。
- 渲染细分对齐原生网格，变化区以约 0.52 m 网格为基准；内部平缓区在 8 mm 高程误差和材质掩膜检查通过后减少三角形，边界细分保持不变，按约 125 m 区块显示。细网格不重复投射阴影，另用原生精度代理保留地形自阴影。路基低于正式路面 3 cm；边缘增加覆盖带，路面外缘有 15 cm 裙边。地图外缘裙边使用相同高程。粗细区块的公共边由数值检查验证。
- 边坡材质携带挖、填、路肩掩膜。树冠半径内与超过 0.1 m 的修改节点相交的树移除，其余树重新落地；河面仍沿用原始数据。

### 下游与入口

`ParcelLayout` 保存 `Grading`、`GradingRevision` 和 `Terrain`，建筑和场景布置沿同一对象传递。地块统计、基础、台阶、附属物、院地、建筑细节、城墙和贴地拾取均改用统一地形接口。旧的环境采样适配器仅用于独立规划测试/兼容调用；正式装配拒绝没有 03B 或混用来源的输入。

建筑仍按整个占地最高点确定安全基础，保留原有基础高差、屋顶占地和通院检查。普通住宅在修整地形上优先选择较高的临街门位，并将门口地面到门槛的可接受高差收紧到 0.35 m，促使候选回退到较浅体量；公共建筑保留 0.8 m 限制。街面落点与修整地形一致，门槛到街面的剩余高差由台阶解决。不能满足限制的住宅保留空地，报告同时记录修整前后建筑数量和入口高差，不能将减少建筑数量解释为地形本身的改善。

### 正式路面与导航

- `RoadSceneBuilder` 以同一世界网格裁切权威道路占地和广场，保存 `SurfaceId / RoadId / NodeId / Paving`。近景 0.5 m、远景 2 m，曲率较大处再局部细分，近景插值与接缝误差限制在 5 mm。
- 128 m 路面区块与远近可见距离；正交相机按视野大小切换，俯瞰时另合批减少提交次数。院地使用同类分块/细节控制，铺装纹理带 mipmap；每块近景路面使用一个静态凹多边形碰撞，地形使用分块高度图。导出还包含建筑、附属物、示意城防和挡土墙碰撞。
- `configs/road_construction.tres` 定义石铺、卵石、压实土、窄土巷和车辙土路的分类及装配选项。`road_surface.gdshader` 使用内置确定性纹理数组；可通过材质资源覆盖和 `MaterialKey` 替换外部美术。当前为程序化示意材质。
- 导航直接由连续道路/广场占地构造，无烘焙。为避免铺装面片接缝和微小布尔边造成断路，导航单独简化 2 cm 以下轮廓细节、细分长边并补齐 T 形连接；它保持同一占地区域，采样设计高程，不复制每个路面渲染三角形。
