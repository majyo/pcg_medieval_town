# 场地采样 · 第一阶段方案

> 状态：第一阶段已完成（第 1–4 步）。第二阶段见 §7。基于节点图架构（[ARCHITECTURE.md](ARCHITECTURE.md) §2–5）。

## 1. 目标与范围

第一阶段只做两件事：

1. **采样**：把地形、水文等与建城有关的信息，采成节点图里一组独立的数据键（下称“场”）。
2. **可视化**：每个场都能在地面上着色显示、在鼠标探针里读数、在右侧面板看到摘要。

判断一件事属不属于第一阶段的标准：**输出是不是一个带单位的物理量或可直接测量的几何**（高程 m、坡度 °、离水距离 m、高出水面 m）。凡是带权重、偏好或“好不好”的东西（适宜性评分、城址打分、渡口评价、可建设判定的阈值）都留给第二阶段。

**水文只做建城需要的最基础数据**：哪里是水、离水多远、比水面高多少。不做径流、汇水、洼地、水系提取、洪水模拟这类“真实”水文——这张图只有一条河，城市只需要知道近水、取水方便、不被淹这几件事，而这些都能从上面三个量直接看出。

明确不做：

- 不改 `site` 键、`SiteAnalysis` 和它下游的任何节点。三个测试种子生成的城镇必须逐位不变。
- 不改地形生成（`TemperateMapData`），也不改 `ITerrain`：现有的 `NearestRiver`（距离、水位、半宽）已经够用。
- 不做评分、选址、渡口/桥位评价、道路相关的东西。

## 2. 现状与问题

- `SiteAnalysis` 一个节点同时做了“采样”和“判定”：在 8 m 网格上读 `Sample()`，再按阈值写出 `SiteBlock`。采样结果（高程、坡度、适宜性）存在 `Site` 里，但只有 `Block` 能被看到（`CityLayer.Site` 的色块）。
- 坡度、林地、适宜性来自地形内部约 5 m 的分析网格，城市侧拿不到自己网格上的坡度算法，换不掉。
- 水的信息只有“最近河段多远”，城市拿不到成格的“离水多远、比水面高多少”，也看不到。

## 3. 节点与数据

### 3.1 “场地采样”分组

全部节点排在 `TownGraph.Create` 最前面（`SiteAnalysis` 之前），只读地形和彼此的键，不被现有节点读取。

| 节点 | 读 → 写 | 内容 | 主要参数 |
| --- | --- | --- | --- |
| `SampleGrid` 采样网格 ✅ | 地形 → `site.grid` | 覆盖全图、以原点为中心的规则网格 | 格距 m（默认 4，范围 2–16） |
| `SampleHeight` 高程 ✅ | grid → `site.height` | 格心高程。每格取 k×k 个子样本的平均，滤掉米级起伏，避免网格混叠 | 每格子样本（1–4，默认 3） |
| `SlopeAspect` 坡度坡向 ✅ | height → `site.slope`、`site.aspect` | Horn 3×3 差分。坡向是下坡方向的方位角（北为 −Z，顺时针），平地无坡向 | 平地阈值 ° |
| `SurfaceWater` 地表水 ✅ | height、地形 → `site.shore`、`site.above_water` | 离水距离：到最近河段河道边的距离（`NearestRiver` 距离 − 半宽，水里为负）。高出水面：采样高程 − 最近河段水位 | 无 |
| `LandformPosition` 地形位置 ✅ | height → `site.relief` | 地形位置指数 TPI：高程减去周围边长 2R 方窗的平均高程（m，积分图计算，耗时与 R 无关）。正为岗地/台地边缘，负为谷地 | 半径 R m（默认 60） |
| `SampleForest` 林地 ✅ | grid、地形 → `site.forest` | 林地覆盖 0–1（取自 `Sample().Forest`） | 无 |

“是不是水面”不单独成键：离水距离 < 0 就是水面。河道边按半宽计，真实水线在它外面 1–6 m（岸坡在那里才升出水面），所以离水距离比到水线的距离略大几米；对建城来说可以忽略，换来的是不需要距离变换。水位也不单独成键：它等于高程 − 高出水面。

拆分依据（ARCHITECTURE §5.3）：每个节点对应一个可能单独替换的决策。将来要支持湖泊或多条河，只换 `SurfaceWater` 和地形实现，其余节点不动。

### 3.2 数据类型（`city/data/Fields.cs`）

所有场都是同一种类型，没有复合类型：

- `SiteGrid`：唯一的网格定义。所有场共用同一个实例，因此格号一致、可直接逐格组合。
- `ScalarField`：一格一个值，带名称、单位、最小/最大/中位数和可选的“无值”标记；可按最近格或双线性取值。可视化、探针、契约检查都只认这个类型。角度类的场（坡向）标为环形：不做插值、摘要不给中位数，因为跨过 360° 时平均没有意义。

一个节点要输出几个量，就写几个 `ScalarField` 键（如 `SlopeAspect` 写坡度和坡向两个键）。

`Site` 的网格几何也用 `SiteGrid`（格号、格心、按位置找格只有这一份实现），但它是自己那张 8 m 网格的独立实例，与采样场不共用；第二阶段重写 `site` 时再统一到采样网格。

### 3.3 规模与耗时预算

默认 4 m 格：500 × 500 = 25 万格。目标是场地采样分组合计 < 0.5 s（Debug）。逐格循环用 `Parallel.For`，取消令牌随 `ParallelOptions` 传入。

## 4. 可视化

### 4.1 地面着色（主视图）✅

视图页“地面 · 着色”与“场地采样”阶段页的“地面着色”：**地表**、**地形适宜性**，以及每个已登记的场（“采样 · 高程”等）。选中一个场时，按 `FieldStyles` 的色带在每个高度网格点上取色，写进 Terrain3D 颜色图（着色器 `view_mode = 1`），颜色贴在真实地面上，透视视角下也能读出地形。

- `GroundSurface.Paint(Func<Vector2, Color>)` 按世界坐标取色，是唯一的分析着色入口（地形适宜性也走它）；`TerrainRenderer.ShowColors` 只转发，不知道“场”是什么。
- `rendering/FieldStyles.cs` 是一张登记表，每项是 `键 → 色带、取值范围、读数格式`。下拉框、图例、探针都从这张表生成，**新增一个场只需加一行登记**。
- 色带：顺序型（高程、坡度、林地）、发散型（TPI、离水距离，以 0 为中点）、分段型（高出水面：0–2 m 与 2–6 m 明显区分）、环形（坡向）。
- 场的值换了（引用变化）才重绘颜色图；正在重新生成时保留上一次的颜色，图例标“等待重新生成”，不闪回地表。
- 地形自带的“高程 / 坡度”两项已由采样场取代；“适宜性（地形）”暂时保留（属于第二阶段要替换的评分）。

### 4.2 叠加图层 ✅

只保留一个，在 `CityView` 里新增，左侧“等高线”开关，默认关闭：

| 图层 | 键 | 画法 |
| --- | --- | --- |
| 等高线 | `site.height` | 行进方块法提等值线，每 2 m 一条细带（0.5 m 宽），每 10 m 一条粗带（1.2 m 宽），贴地抬高 0.4 m，深褐色半透明 |

等值线提取放在 `city/tools/Contours.cs`（将来道路纵断面、地形修整也会用），画线放在 `rendering`。默认 4 m 格下全图约 3.4 万段，直接用数组建网格（`MeshKit.Indexed`）。

### 4.3 探针与图例 ✅

- 鼠标探针遍历 `FieldStyles`，列出光标处所有有效场的读数，例如：
  `(-212, 348)  高程 23.4 m  坡度 3.1°  坡向 西南 214°  离水距离 64 m  高出水面 +4.2 m  地形位置 +1.8 m  林地 12%  可建设`
- 下拉框下方显示当前场的图例：色带 + 两端读数 + 单位。

### 4.4 右侧面板

不需要改界面代码：新节点自动出现在“场地采样”阶段下，摘要来自 `ScalarField.Summary`（范围与中位数；环形的坡向只给有值比例）。

## 5. 不变量（写进 `Contracts`）

| 键 | 检查 |
| --- | --- |
| `site.grid` ✅ | 覆盖整张地图，超出不到一格，以原点为中心 |
| 所有 `ScalarField` ✅ | 使用共用的网格实例；长度等于格数；无非有限值；`Min/Max` 与数组一致 |
| `site.height` ✅ | 与格心 `HeightAt` 之差 < 1 m |
| `site.slope` / `site.aspect` ✅ | 坡度在 [0, 45°]；坡向在 [0, 360) 或为无值 |
| `site.shore` ✅ | 为负的格都是地形水面（`Sample().IsWater`）；地形水面格离河道边不到 8 m |
| `site.above_water` ✅ | 离水 2 m 以内的水面格不高于水位 0.5 m 以上；离水 30 m 以外的格不低于水位 |
| `site.relief` ✅ | 全图平均值接近 0（绝对值 < 0.5 m）；河道深处（离水 < −10 m）至少九成格为负 |
| `site.forest` ✅ | 在 [0, 1]；水面格为 0 |
| 等高线 ✅ | 每个端点在采样高程上取值都等于它的高度（误差 1 cm 内），写在 `Checks`（工具算法，不挂在键上） |

另外沿用现有的节点图检查：不改读到的值、过期按依赖传播（让“高程”过期后只有依赖它的采样节点过期，城镇节点不受影响）、两次生成一致；并检查三个种子下城镇节点的输出与改动前相同。

每一步结束时三个种子都能跑完、检查全过、截图可看。

2. ✅ **地表水**：`SurfaceWater`（`site.shore`、`site.above_water`）；两项登记进 `FieldStyles`；`capture` 增加“高出水面”的城镇透视视角。
3. ✅ **地貌与林地**：`LandformPosition`、`SampleForest`；`Contours` 工具与等高线图层（默认关闭）；`capture` 的“高出水面”城镇视角叠加等高线。
4. ✅ **收尾**：三个种子下各采样视角的截图已核对；坡向改为环形场；截图时同步等高线开关；文档与代码已对齐。

## 7. 留给第二阶段

- 用这些场重写 `site` 的判定（`SiteAnalysis` → 读场的 `BuildableLand`），把 `site` 改名为 `site.buildable`；“易淹”直接由高出水面低于某个阈值判定。
- 适宜性评分与城址选择改为读场：近水（离水距离）但不淹（高出水面 2–6 m 的台地）、地势略高（TPI > 0）、坡度平缓。
- 渡口/桥位评价：沿河找离水距离变化最快（河窄）、两岸高出水面适中的位置。
- 湖泊与多条河：换 `SurfaceWater` 和地形实现即可。
